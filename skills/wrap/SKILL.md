# 세션 종료 루틴

> **순서대로.** 앞 단계의 결과가 뒤 단계의 입력이다 — 건너뛰면 어긋난다.
> **각 단계는 "확인"까지 해야 끝난 것이다.** 확인 없이 다음으로 넘어가지 말 것.
>
> 프로젝트 고유 경로(키트 위치·칸반 사용 여부)는 그 프로젝트 `CLAUDE.md` §9에 적혀 있다.

## 0. 이번 세션에 뭘 했는지 먼저 뽑는다

세션 끝은 **컨텍스트가 가장 얕아진 시점**이다. 기억으로 쓰면 빠뜨린다. 먼저 사실을 손에 쥔다.

```
git log --oneline <세션 시작 시점>..HEAD
git status --short
```

- 세션 중 만든 커밋 목록
- 아직 미커밋인 변경 목록 — **어느 줄이 내 것이고 어느 줄이 사용자 것인지** 갈라둔다

**확인**: "한 일"을 커밋·파일 근거로 열거할 수 있나. 기억에만 의존한 항목이 있으면 그건 확인하고 적는다.

## 1. 칸반 정리

`kanban` 스킬을 열어 그 절차대로. 끝낸 카드 → `완료`, 손대기 시작한 카드 → `진행 중`, 새로 생긴 할 일 → 카드 생성.

⚠️ **"완료"는 동작을 확인한 것만.** 커밋했다고 완료가 아니다. 애매하면 `진행 중`으로 두고 **남은 것을 카드 본문에** 적는다.

⚠️ **카드를 닫기 전에도 코드로 대조한다.** `brief`의 대조 절차는 세션 *시작*에만 도는데 **닫는 쪽에도 같은 함정이 있다** —
문서·카드에 "남았다"고 적힌 게 **이미 끝나 있어서 카드만 괜히 열려 있는** 경우다.
(2026-08-05: "원티드 포스터·전용 초상화가 남았다"고 적혀 있었지만 **배선은 다 돼 있었고 그림 파일만 임시본**이었다.
사용자가 *"안 끝난 거 있어? 다 된 거 아니야?"* 라고 물어서야 확인했다.)
→ 닫기 전에 **"남았다"는 항목 하나를 `grep`·씬 조회로 확인**한다. 아트 대기처럼 **코드 작업이 아닌 잔여물이면 카드를 닫고**
"아트 대기" 목록으로 옮긴다 — 그걸로 카드를 열어두면 보드가 영원히 안 줄어든다.

⚠️ **카드 본문에 "남았다"고 적힌 것도 에셋·파일로 1건 확인한다.** 바로 위 규칙은 *카드를 닫을 때*만 말하는데,
**카드를 옮기거나 인용할 때**도 같은 함정이다 — 카드는 손으로 쓰는 문서라 **결정이 반영 안 된 채 낡아 있다.**
트리거 자명 — *카드에 적힌 할 일을 다른 문서·카드로 옮기려는 순간.*
(2026-08-25: 「사운드」 카드에 "효과음 14종 고르기"·"git 포함 결정"이 미완으로 남아 있었지만
`SfxLibrary.asset`엔 **이미 15개가 꽂혀 있었고** `Assets/Sound`는 **진작 `.gitignore`에** 있었다.
「아트 리소스」는 더했다 — 사용자가 항목 뒤에 *"지금도 괜찮던데"*, *"그냥 기본 오브 크기 조정해서 써"* 라고
**결정을 적어뒀는데 체크박스가 비어 있다는 이유로** 살아 있는 할 일로 취급했다. 6건이 그랬다.)

⚠️ **같은 사실의 사본을 두 곳에 두지 말 것.** 두면 반드시 한쪽만 낡는다.
트리거 자명 — *이미 어딘가 있는 표·목록을 다른 문서에 또 적으려는 순간.* **원본 한 곳만 두고 나머지는 포인터만.**
(2026-08-25: HANDOFF 안에 일정표가 두 군데 있었는데 사용자가 조건을 하나씩 줄 때마다 한쪽만 고쳐져
**하루에 세 번 어긋났다.** 「태리미가 할 일」 절도 날짜 카드와 두 번째 진실이 돼서 결국 10블록을 통째로 지웠다.)
**확인**: 옮긴 카드마다 "무엇을 근거로 완료라 판단했는지" 한 줄로 말할 수 있나. 그 근거가 **문서가 아니라 코드·씬**인가.
(칸반을 안 쓰는 프로젝트면 이 단계는 건너뛴다.)

## 2. HANDOFF.md 갱신

칸반을 정리한 **뒤에** 그 결과를 반영한다 — 칸반이 원본, HANDOFF는 미러다.

- 빌드 상태 / 미해결 이슈 / 다음 할 일
- ⚠️ **추가만 하지 말고 삭제도 할 것.** 이미 해결된 "~해야 함"이 남으면 **다음 세션이 그걸 사실로 읊는다.**
  이번 세션에 해결한 항목을 지웠는지 훑어볼 것.

**확인**: HANDOFF의 "다음 할 일"이 칸반의 `시작 전`·`진행 중`과 일치하나.

## 3. 세션 일기

`<키트>/journal/YYYY-MM-DD.md` (틀: `<키트>/templates/JOURNAL_ENTRY.md`)

- **게임이 아니라 *과정*의 회고.** 오늘 워크플로에서 뭐가 매끄러웠고 뭐가 막혔나, 다음엔 뭘 바꿀까.
- 하루 두 번째 세션이면 같은 파일에 `## 세션 N` 블록 추가.
- **`[→ Kit]`으로 표시한 교훈은 실제로 반영까지 한다 — 두 곳 다.**
  템플릿(`templates/CLAUDE.md` 또는 키트 스킬) **+ 현재 프로젝트의 `CLAUDE.md`**.
  템플릿에만 넣으면 *다음* 프로토타입만 덕을 보고 지금 프로젝트는 계속 빈손이다(2026-08-02 일기에서 발견).
- 짧게. 안 쓰게 되는 게 최악이다.

**확인**: 파일이 생겼나. `[→ Kit]`을 적었다면 **반영도 했나.**

## 4. 커밋 + 푸시

- 변경 파일 전체 스테이징 → **현재 브랜치**로 푸시.
  `git branch --show-current`로 확인할 것 — **`main`이라고 넘겨짚지 말 것**(`master`인 저장소가 있다).
- ⚠️ **한글 커밋 메시지는 `-m`이 아니라 파일로.** 메시지를 파일에 쓰고 `git commit -F <파일>`.
  here-string은 따옴표·백틱이 섞이면 쪼개져 실패한다.
- ⚠️ **커밋 직전 `git status`의 모든 줄을 설명할 수 있어야 한다.** 설명 못 하는 줄이 사고다.
  사용자의 미커밋 작업이 섞여 있으면 **커밋 전에 알린다** — 0단계에서 갈라둔 목록을 쓴다.
- ⚠️ **새 디렉터리(`?? xxx/`)가 보이면 커밋 전에 `du -sh`로 용량을 잰다.** git 히스토리는 되돌리기가 가장 비싼 축이라
  한 번 들어간 대용량 바이너리는 history 재작성 없이 못 뺀다. 에셋 팩·음원·동영상은 **"그냥 커밋해"에 섞여 들어오기 쉽다.**
  트리거 자명 — *`git status`에 새 디렉터리가 있는 순간.* 100MB를 넘으면 **커밋하지 말고 먼저 알린 뒤** 대안을 제시한다
  (쓰는 것만 남기기 / Git LFS / 제외). **사용자가 커밋을 지시했더라도 용량은 따로 확인받을 것** — 지시한 사람이 용량을 모르고 말했을 수 있다.
  (2026-08-10: 음원 팩 164MB가 `?? Assets/Sound/` **한 줄**로 들어와 있었다. 608개 중 실제로 쓸 건 14개였다.)
- 키트(`prototyping-kit`)를 고쳤으면 **거기도 따로 커밋·푸시**한다. 저장소가 둘이다.

**확인**: 푸시 후 `git status`가 깨끗한가. 섞인 줄이 있었다면 사용자에게 알렸나. **새 디렉터리 용량을 쟀나.** 키트도 푸시했나.
