## 세션 4 — OrganicFoodShop (발전 피쳐: 업그레이드 UI + 수 표기)

**목표**: 발전(progression) 피쳐로 진입 — 업그레이드 상점 UI를 다듬고(카테고리 탭), 인크리멘탈 게임 특성상 커지는 숫자를 읽기 쉽게.

**한 일**:
- 업그레이드 UI에 **상점/농장 탭(책갈피)** 추가. `upgrades.json`의 distinct `section`으로 **탭 자동 생성** → 섹션 추가하면 탭도 자동. 선택 탭만 필터링, 인라인 헤더 제거.
- **K/M/B 수 축약** 공용 유틸(`NumberFormat.Short`) + 돈·가격류 호출부 교체(HUD 잔액·획득팝업, 업그레이드 비용, 판매가/씨앗가). 수량/EXP는 스코프에서 제외.
- (유저 주도) 업그레이드 시스템 본체·GameHud·물뿌리개 범위 업글·MainScene/FarmArea·ShopArea 프리팹 등 진행 — 나는 그 위에 UI/표기만 얹음.

**과정 — 잘 된 것**:
- **plan 모드를 교차 변경에 활용**: K/M은 여러 파일 호출부를 건드리는 일이라, 먼저 표시 지점을 전수 grep → 스코프(돈·가격 vs 수량 포함)를 질문으로 확정 → 유틸 1개 + surgical 교체. 범위가 안 샜다.
- **데이터 기반 탭**: 탭을 하드코딩 안 하고 JSON 섹션에서 생성 → 작은 결정인데 확장성 공짜.

**과정 — 막힌 것 / 마찰**:
- 세션 사이/중에 **유저가 코드를 많이 고쳐둠**(업그레이드 시스템·GameHud·물범위·MainScene 단일씬화 정황). 내 기억/HANDOFF가 "Farm·Shop 두 씬"으로 남아 있어 전제가 어긋날 뻔. 매번 파일을 새로 읽어 확인한 게 안전판이었음.
- 숫자 표시 지점을 일부 이미 알면서도 전수 grep을 다시 돌림(중복). 그래도 빠뜨림 방지엔 이득.

**다음에 바꿀 것**:
- **유저가 사이에 많이 손댄 낌새면, 계획 전에 씬/아키텍처 전제부터 재확인**(예: 두 씬→MainScene 단일씬 전환됐는지). HANDOFF의 "현재 상태"를 곧이곧대로 믿지 말고 파일로 검증.

**메모**:
