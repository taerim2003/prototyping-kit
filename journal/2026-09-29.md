# 2026-09-29 — 스킬 밸런스 테스팅 방식 교체와 진화 수치 구조 정리

## 무엇을 했나

스킬 밸런스 측정 방식을 시험장(gym)에서 정주행 기반으로 갈아치웠고, 진화체의 쿨타임과 피해가 에셋 한 장에서 정해지도록 코드 배율 16종을 걷어냈다. 44종 진화의 쿨타임·피해·타수를 전부 새로 넣었고 `balance`·`balance-loop` 문서를 다시 썼다.

커밋은 하지 않았다. 작업 트리에 다른 세션의 미커밋 작업이 스크립트 28개에 섞여 있고 `PlayerSkills.cs`를 양쪽이 같이 만져서 파일 단위로 가를 수 없었다.

## 매끄러웠던 것

**"값을 정하기 전에 그 값이 어디서 오는지 전부 센다"가 이번에 제대로 먹혔다.** 진화 쿨타임 표를 만들 때 코드 경로를 재현하는 스크립트를 짜서 계산했고, 그 덕에 시전 시점 배율(화살 +3초·화살비 ×2)을 빠뜨린 것을 사용자가 "화살비 쿨이 4초보단 길었던 것 같은데"라고 지적했을 때 **어디를 놓쳤는지 한 번에 찾았다.** 손으로 계산했으면 못 찾았다.

**적용 스크립트를 미리보기(`--dry`)로 먼저 돌리는 습관이 44개 에셋을 두 번 구했다.** stage 2가 1차의 Lv1 상태에서 출발하는 버그를 미리보기 출력에서 잡았고, 쿨 칸이 없는 진화 9종도 적용 전에 드러났다.

## 막힌 것

### 문체 지적을 다섯 번 받았다

사용자가 보고서 문체를 다섯 번 고쳐 줬다. 도식적이다 → 비유가 많다("슬롯 가계부"·"손이 닿지 않는다") → 문장이 너무 분절적이다 → 독자가 아는 것을 설명한다 → 구어체 동사를 쓴다("듣는다"·"먹힌다"). 매번 한 방향으로 고치면 반대쪽으로 넘어갔다.

**원인은 문체가 아니었다.** 데이터가 없는 상태에서 인과가 이어진 글을 쓰려 하니 재료가 없고, 그러니 비유로 덮었다. 실제로 낙뢰 메커니즘을 세 군데 지어냈다("근처 적에게 연달아 옮겨간다"는 진화 전엔 없는 기능이고, 애초에 그 코드는 아무도 켜지 않는 죽은 코드였다). **비유가 늘어나는 것은 사실을 모른다는 증상이다.** 이걸 메모리 두 개로 남겼다.

### 코드 주석을 믿고 두 번 틀렸다

낙뢰 체인을 "힘 패시브 연계 R1 진화에서 열린다"고 썼는데 주석을 그대로 옮긴 것이었고, 실제로는 `ChainEnabled`를 켜는 곳이 프로젝트 전체에 없었다. 리프레시도 "레벨업으로 안 오른다"고 썼는데 `ApplyEvolvedLevelBonus`에 이미 들어 있었다. `ApplyLevel`만 보고 그 함수를 안 읽었다.

CLAUDE.md §7에 "문서·카드에 적힌 건 전부 낡는다"가 있는데 **코드 주석에는 그 경계심이 안 걸렸다.** 주석도 같은 취급이어야 한다.

### 문구만 보고 44칸을 채웠다

진화별 레벨업 축 표를 노션 문구만 읽고 유추해서 만들었다. 검은 화살에 관통 축을 넣었는데 코드에 `pierce = int.MaxValue`가 있고 **바로 아래 주석에 "그 대가로 ExtraPierce가 이 진화에선 죽은 스탯이 된다"고 적혀 있었다.** 사용자가 "제대로 검수 조사한 거 맞아?"라고 물어서 철회했다.

다시 만들 때는 `PathTier` 분기 126곳을 기계적으로 뽑아 코드 근거를 칸마다 달았다. **사용자가 "문구 유추도 같이 해야지, 왜 하나만 하려고 그래"라고 한 것이 정확했다** — 문구는 의도, 코드는 구현이고 둘이 어긋나는 지점 자체가 결과다. 실제로 그렇게 하니 "내 지휘를 따라!"가 공격을 아예 안 한다는 것과 피뢰침이 발동 확률 축을 죽인다는 것이 나왔다.

### 인라인 node -e 와 노션 이스케이프

CLAUDE.md §8-1이 막는 패턴을 둘 다 밟았다. `node -e`로 한글과 `\n`이 든 치환을 11건 넘겼고(다행히 통과했지만 확인이 필요했다), 노션에 유니코드 이스케이프로 한글을 보내 **`갱슱`·`없육습니다`·`메듀사`로 글자가 깨졌다.** 두 규칙이 메모리와 kanban 스킬에 이미 있는데 급할 때 그대로 밟았다.

## 다음엔 뭘 바꿀까

**측정 방식을 논의할 때 "지금 값을 먼저 재고 시작한다"를 더 앞으로 당긴다.** 트리 완성률과 이터레이션 소요 시간을 물었을 때 실측으로 답했고, 그 답이 사용자의 직관과 갈리는 지점(정주행에서 어려움 목표는 이미 트리 98~100%)이 곧 설계 입력이 됐다. 반대로 2차 진화 도달률은 내가 "설계 위험"으로 먼저 단정했다가 사용자가 "1차 진화 개수도 같이 볼래?"라고 해서 재보니 **판당 1차가 평균 2.63개, 85%가 2개 이상**이었다. 재료는 충분하고 조율만 실패한 것이었다. 위험을 말하기 전에 한 번 더 쪼개 재야 한다.

## AI 협업 체크

**사용자가 지적해 준 것**

- 문체 다섯 건(도식적 · 비유 · 분절 · 아는 것 설명 · 구어체)
- 낙뢰 체인이 레거시라는 것 — 내가 주석을 믿고 기능이 있다고 썼다
- 리프레시 레벨업 효과가 이미 고쳐져 있다는 것
- 검은 화살의 관통이 죽은 스탯이라는 것과 표 전체가 유추였다는 것
- 미니 독수리 "본체의 24배"가 내 오독이라는 것 — 대상 수를 곱셈으로 읽었다
- 본체와 파생을 섞어 놓은 것 — 대체형 진화는 배율이 있을 이유가 없다
- 화살비 쿨이 더 길었던 기억 — 시전 시점 배율을 빠뜨렸다
- 하늘 파쇄기는 쿨타임 개념이 없는 상태형이라는 것
- 전탄발사 15타가 위험하다는 것 — 타수가 펠릿마다 곱해진다
- 다이너마이트의 12타는 코드 루프가 아니라 타수로 내야 한다는 것

**내가 추측으로 진행한 것**

- 쿨 칸 배정 규칙(감소 비율 구간별 0~4칸)을 내가 정했다
- 칸을 내줄 축을 "그 커브에서 가장 여러 번 나오는 축"으로 기계적으로 골랐다
- 타수를 "한 시전의 데미지 숫자 30~40개" 기준으로 역산했다
- 트리 완성률 농장 70 / 해변 85 / 우주 100을 내가 정했다
- 슈퍼 로켓 폭발 120% → 80%를 "진화체 폭발" 지시에 포함시켰다

## 세션 N — 적 스프라이트 확인 · 크라켄 피격 범위 (BlueberryDefense)

**목표**: 새로 적용한 적 그림 3종(우주선 · 우주콩콩이 · 크라켄)을 실제 게임 화면으로 찍어 보여 준다.

**한 일**: 타이틀 → 맵 선택 → 판 시작의 정상 흐름으로 우주·해안가 맵에 들어가 해당 적을 화면 안에 스폰해 찍었다. 크라켄 캡처 위에 실제 콜라이더를 빨간 사각형으로 그려 보여 줬고, 사용자가 보고 "두 배로"를 정했다. 보스 프리팹은 세 맵이 공유하므로 `MapDefinition.bossColliderSize`를 새로 두고 해안가만 2×2로 바꿨다. 같은 흐름으로 다시 찍어 확인했다. 중간에 "Unity가 백그라운드 작업을 많이 돌린다"는 질문을 받아 원인을 로그로 갈랐다(다른 세션의 에셋 55개 재작성 + 재시작 후 검색 색인).

**과정 — 잘 된 것**: 피격 범위를 값으로 말하지 않고 캡처 위에 그려 보여 준 것. 사용자가 그림 한 장을 보고 바로 결정했다. Unity 부하 질문은 추측 대신 `Editor.log`의 `Start Indexing`·임포트 대상 목록과 프로세스 시작 시각, 파일 mtime을 대조해 갈랐고, 다른 세션에 직접 물어 확인까지 했다. 플레이모드 전후로 병렬 세션에 알린 것도 충돌을 막았다.

**과정 — 막힌 것 / 마찰**: `SendUserFile`로 보낸 캡처가 VSCode 화면에는 안 보여 사용자가 "사진 어디에 보냈는데?"라고 물었다. 파일 카드는 원격 화면용이다. 커밋은 못 했다 — 고친 `EnemySpawner.cs`·`HANDOFF.md`에 다른 세션의 미커밋 변경이 섞여 있다.

**AI 협업 체크**:
- 추측으로 진행한 것: "가운데를 중심으로"를 기존 콜라이더 중심(y −0.4)으로 읽었다. 그림 중심으로 읽을 수도 있었다 → HANDOFF 확인 대기에 적었다.
- 사용자가 지적해 준 것: 보낸 사진이 안 보인다는 것.

**다음에 바꿀 것**: 캡처를 보낼 땐 파일 카드와 함께 로컬 경로 링크를 답변에 같이 적는다(메모리에 저장).
