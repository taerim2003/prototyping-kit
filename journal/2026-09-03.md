**과정 — 막힌 것 / 마찰**:
- 🔴 **세이브 백업을 엉뚱한 레지스트리 키에 떴다.** 세이브 초기화 버그를 재현하려고 백업했는데,
  Unity는 **에디터와 빌드가 서로 다른 키**를 쓴다(`Software\Unity\UnityEditor\...` vs `Software\...`).
  빌드 쪽을 뜨고 "안전하다"고 판단했고, 실제로 지워진 에디터 세이브는 복구가 안 됐다.
  `reg import`가 성공으로 끝나서 더 헷갈렸다. 도감·맵 클리어 진행도가 날아갔다(태리미가 "그대로 둔다" 결정).
- 🔴 **bash 헤어독이 JS의 백슬래시를 먹는다.** 검산 스크립트의 `/\\n/`이 `/\n/`으로 망가져
  **복원 규칙이 한 번도 안 태워진 채 "통과"로 보였다.** 픽스처의 ⏎ 개수를 같이 세지 않았으면 못 봤다.
- **인계 문서의 "못 한다"를 그대로 믿을 뻔했다.** HANDOFF에 *"체크박스는 API로 못 건드린다"* 고 적혀 있었는데
  태리미가 "체크 다 쳐야지"라고 해서 시도해 보니 **`update_content`로 잘 됐다.** 그 주장은 `update-a-block` 얘기였다.
- **플레이모드 왕복이 여전히 많다.** 타이틀→캐릭터→맵→배틀을 이번 세션에만 5번 밟았고 매번 4~6 호출을 썼다.
  게다가 방어를 못 해서 30초면 죽어 측정이 중간에 끊겼다(레벨업·게임오버 모달로 `timeScale=0`).

**다음에 바꿀 것**:
- **[→ Kit] 세이브(PlayerPrefs)를 지우는 테스트 전에는 *에디터 키*를 백업한다.**
  Windows에서 에디터는 `HKCU\Software\Unity\UnityEditor\<회사>\<제품>`, 빌드는 `HKCU\Software\<회사>\<제품>`.
  빌드 키를 떠 놓고 안전하다고 판단하면 **백업은 멀쩡한데 지워진 건 복구가 안 된다.**
  트리거 자명 — *`PlayerPrefs.DeleteAll` 경로를 밟는 테스트를 짜는 순간.*
- **[→ Kit] 스크립트 파일은 bash 헤어독으로 쓰지 않는다 — Write 툴로 쓴다.**
  헤어독이 백슬래시를 먹어 **정규식이 조용히 무력화**된다. 증상이 "검사 통과"로 나와서 원인을 안 가리킨다.
  트리거 자명 — *`cat > file <<EOF` 로 `.js`·`.ps1`을 만들려는 순간.*
- **[→ Kit] 문서의 "이건 못 한다"는 인용 전에 한 번 해 본다.**
  기존 규칙("문서에 적힌 건 낡는다")은 *할 일*과 *해법*만 말해서 **불가능 주장**엔 발동을 안 했다.
  못 한다는 말은 시도를 없애서 **틀려도 영원히 안 드러난다.** 트리거 자명 — *"~는 못 한다"를 근거로 대안을 찾으려는 순간.*
