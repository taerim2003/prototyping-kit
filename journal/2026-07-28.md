## 세션 1 — 블루베리 디펜스 (세션13)

**목표**: 스테이지 "특징 강화" — BTD6식 능력시험 벽 스테이지. UFO 리워크(수송선화) + 라이더 신규 적 + 방패/UFO 전용 벽 스테이지 + 11+ 밸런싱. 부수적으로 죽은 트리 UI 정리.

**한 일**: UFO를 좌진 유닛 → 화면 위에서 하강·부대 투하·상승 퇴장하는 수송선(`isCarrier` 모드)으로 리워크(투하 전 격추 시 부대 취소 = 대공 보상). 라이더 블루베리 신규 적(프리팹·3프레임 애니·EnemyDef·맵 배선)을 script-execute로 프로그래밍 생성. StageTable에 9=방패 벽·13=UFO 벽 추가 + 11~15 상향. 전부 컴파일/데이터 검증까지. 실플레이는 다음으로.

**과정 — 잘 된 것**:
- **설계 결정을 먼저 물었다.** UFO 리워크의 로드베어링 3개(궤적/격추보상/투하구성)를 AskUserQuestion으로 확정한 뒤 구현 → 프리팹 다시 만드는 재작업 없었음. 스테이지 밸런스도 표로 제안→승인→반영 순서.
- **애셋 생성을 하드 YAML 대신 `script-execute`(에디터 C#)로.** 애니클립/컨트롤러/프리팹의 GUID·fileID·피벗을 API가 처리 → 손으로 YAML 짜다 깨지는 리스크 회피.
- **좌표를 하드코딩 대신 `Camera.main` 기준 런타임 계산** → 레인 Y를 몰라도 견고.

**과정 — 막힌 것 / 마찰**:
- **프리팹 스프라이트 교체가 1차에 조용히 실패.** `LoadPrefabContents`+`SaveAsPrefabAsset` 직후 재임포트한 스프라이트 할당이 안 먹혀 verify 로그로 잡고 2차 repair. 검증 로그를 붙여둔 게 유일한 방어선이었음 — 애셋 생성 후 **항상 되읽어 검증**하는 습관이 값을 함.
- **BALANCE_MAP.md의 수치가 stale했다.** UFO HP를 "68→45"로 제안했는데 실제 에셋은 40이었음. 문서 대신 라이브 에셋을 읽었어야. 그리고 그 BALANCE_MAP은 세션 중 사라짐(알고 보니 유저가 의도적으로 삭제) → 잠깐 조사 detour.

**AI 협업 체크**:
- 추측으로 진행한 것: 거의 없음. UFO는 물어보고 감. 다만 밸런스 수치를 **stale 문서(BALANCE_MAP)를 근거로** 제안한 건 실수 — 라이브 에셋을 먼저 확인했어야.
- 유저가 명시 안 한 전제: "스테이지 길게"의 의미(물량 vs 스테이지 수)를 내가 물량으로 오해 → 유저가 "스테이지 수"로 정정. 애매한 한 줄 요구는 구현 전 방향 확인이 나았음.
- AI가 잘한 자율 결정: 사라진 BALANCE_MAP을 **임의 복원하지 않고 flag** → 유저 의도(삭제)와 일치. 되돌리기 어려운 판단에서 확인부터 한 게 맞았음.

**다음에 바꿀 것**:
- 밸런스 수치는 **BALANCE_MAP이 아니라 해당 에셋을 직접 읽어** 확인할 것(문서는 stale 가능). **[→ Kit]** 밸런스 맵 류 문서 상단에 "수치는 참고용, 라이브 에셋이 정답" 경고 이미 있으나 실천 필요.
- 애매한 1줄 요구("~길게", "~강화")는 **구현 착수 전 해석을 한 번 되물을 것**.

**메모**: 승천별 스테이지 수 확장(승천1=20/2=25/3=30)은 유저 요청으로 다음 세션 작업 — HANDOFF `📌 다음 세션 예정`에 접점 6개 스펙 기록해둠. 유저가 BALANCE_MAP·RETROSPECTIVE를 의도적으로 삭제(정리).

## 세션 2 — 블루베리 디펜스 (세션14)

**목표**: 세션13 플레이테스트 피드백 4건(라이더 스프라이트 반전·화질 / UFO 투하 위치·횟수·물량 / 거대+미니 회오리 미발동 / 보스 사망 UFO가 플레이어 머리 위) 수정 + 스킬트리 안개 재설계.

**한 일**: 4건 전부 근본원인 찾아 수정 — 라이더는 스프라이트 임포트(Bilinear→Point·압축off) + 프리팹 FlipX. UFO는 Enemy.cs 캐리어 로직(등장 x 범위·호버 고도·3회 투하·리젠트 혼합). 회오리는 `FireWhirlwind`의 else-분기가 미니 스폰을 삼키던 것. 보스 UFO는 분출 캐리어 전용 `EmergeAsBurstCarrier`. 스킬트리는 인접 노드 `?` 마스킹 해제. 매 수정 후 리임포트·컴파일 검증(에러 0).

**과정 — 잘 된 것**:
- **낡은 주석보다 라이브 코드/씬을 신뢰.** 캐리어 코드 주석이 "플레이어=좌측"이라 적혀 있었는데, 실제로는 적 이동방향(`Translate right`)·스포너 배치·기본공격 방향(`left` 머즐)을 교차검증해 **플레이어=우측**임을 확정. 주석만 믿었으면 UFO 회피 방향을 반대로 고칠 뻔.
- **편집 전 원인 특정.** 4건 모두 "증상→해당 라인" 먼저 짚고 최소 수정. 특히 회오리 버그는 `if/else` 구조 한 곳이라 스폰 블록을 조건 밖으로 빼는 것으로 끝.
- **불확실성을 숨기지 않고 flag.** 라이더 반전은 원본 그림을 볼 수 없어 "둘 다 FlipX=1인데 반전돼 보인다 → 원본이 반대 방향" 추론으로 고치되, 확정 아님을 유저에게 명시. UFO 총물량 12~15/캐리어도 "과하면 이 필드로 조절"이라 flag.

**과정 — 막힌 것 / 마찰**:
- **주석이 코드와 정반대라 좌표계 확정에 detour.** 캐리어 주석의 "좌측=플레이어"를 반증하느라 3개 파일(Enemy·EnemySpawner·PlayerSkills)을 교차확인. 고친 김에 주석도 바로잡음.

**AI 협업 체크**:
- 추측으로 진행: 없음. 라이더 방향만 추론 요소였고 그건 명시적으로 flag.
- 유저 암묵 전제: UFO 투하 "물량 좀 늘려"의 정도가 애매 → 3회×(4~5)=12~15로 잡되 조절 지점을 알려 유저가 판단하게 넘김.
- AI 자율 결정 잘한 것: 낡은 주석 대신 코드 교차검증으로 좌표계 확정, 그리고 그 주석을 바로 수정. 되돌리기 쉬운 문서 오류는 즉시 고치는 게 맞았음.

**다음에 바꿀 것**:
- **코드 주석이 방향/좌표를 단정할 때 한 번은 코드로 대조.** 이번처럼 주석이 stale/역방향일 수 있음. (세션13의 "문서 대신 라이브 에셋" 교훈의 코드판.)

**메모**: 라이더 반전은 원본 그림 방향 추론이라 유저 플레이 확인 대기. 스킬트리 안개는 이제 "인접=전공개 / 2링크 이상=완전은폐"로 단순해짐.
