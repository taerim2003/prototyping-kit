## 세션 2 — 블루베리 디펜스 (세션 24, 메타 세션)

**목표**: 노션 칸반보드를 **할 일·일정의 단일 원본**으로 삼는 워크플로를 세우고, HANDOFF를 그 미러로 재구성. 시작/종료 루틴에 칸반 단계를 박기.

**한 일**: 칸반 "POC 할일"(오늘 신설, 5장)을 조회해 카드마다 **코드로 미구현을 확인한 뒤** HANDOFF "다음 할 일"을 교체. CLAUDE.md에 §6-2(칸반 원칙 5개 + 콘텐츠 동결 원칙 + 조회 절차) 신설, §7·§9 루틴에 조회·정리 단계 추가. 조회를 자동화하는 `.claude/scripts/notion-kanban.ps1` 작성·검증.

**과정 — 잘 된 것**

- **카드 5건을 전부 코드로 대조한 것.** 특히 "보물상자로 스킬 진화"는 **최근 커밋 제목("보물상자 연출 교체", "보물상자 재설계")과 겹쳐서** 이미 끝난 일처럼 보였다. 실제로는 진화가 아직 `EvolutionItemPickup` → `ShowEvolutionReward()`로 보물상자와 **완전히 별개 경로**였다. 제목만 보고 "이미 했다"고 보고했으면 사용자가 요청한 일이 통째로 증발할 뻔했다. 세션23에서 정리한 "문서를 사실로 읊지 말 것"이 이번엔 **칸반 카드** 상대로 재현됐다 — 원본이 노션으로 바뀌어도 함정은 그대로다.
- **스크립트를 만들고 곧바로 실데이터로 돌린 것 — 여기서 버그 2개가 나왔다.** ① "가장 최신 저장 파일"을 읽게 짰더니 병렬 세션이 남긴 **40건짜리 부분 덤프**가 더 최신이라 보드가 5장→2장으로 잘렸다. ② id로 병합하게 고쳤더니 이번엔 사용자가 만들었다 지운 **테스트 카드가 되살아났다**(`in_trash: true`, 검색은 휴지통을 안 준다). 안 돌려보고 "만들었습니다"로 끝냈으면 **다음 세션이 잘린 보드를 진실로 믿었을 것**이다.
- **`git status`에서 줄이 *사라진* 걸 조사한 것.** 세션 시작 스냅샷엔 있던 파일들이 커밋 직전엔 없었다. 사용자가 세션 중 커밋 2개를 만든 게 원인이었는데, 그 김에 `.gitignore`의 `.claude/*`가 **내가 만든 스크립트를 미추적으로 만들고 있다**는 걸 발견했다. CLAUDE.md는 그 스크립트를 시작 루틴의 필수 단계로 참조하는데. "늘어난 줄"만 보고 "사라진 줄"을 안 봤으면 못 잡았다.

**과정 — 막힌 것 / 마찰**

- 🔴 **토큰 원인을 오진할 뻔했다.** 사용자가 "노션 MCP가 토큰을 많이 먹는 것 같은데 설정이 안 돼서 그런 거지?"라고 물었고, 150KB 검색 응답이 딱 범인처럼 보였다. 실측해보니 **그 150KB는 한도 초과로 파일에 떨어져 컨텍스트엔 안 들어온다 — 거의 공짜**였다. 진짜 비용은 ① 카드 본문(필요한 것) ② **MCP 툴 스키마**(하나당 공통 `$defs` 2KB, 8개 호출)였다. 그대로 동의했으면 **검색을 줄이는 엉뚱한 최적화**를 했을 것이다. 세션23의 "감으로 답하지 말고 재라"가 또 먹혔다.
- **MCP 서버 버전 불일치는 여기서 못 고친다.** 서버는 구버전 Notion API를 말하는데 노출된 툴셋은 신버전(data source 기반)이라 `query-data-source`가 **항상 400**이고, 구버전용 `databases/{id}/query` 툴은 아예 없다. 그래서 "전체 검색 → 파일 → 파싱"이라는 2단계 우회로가 **정상 절차로 굳었다.** 판별법과 함께 "서버가 고쳐지면 통째로 폐기하라"고 CLAUDE.md에 적어뒀다.
- **BOM이 편집할 때마다 날아갔다.** 스크립트가 한글 상태명(`시작 전`/`진행 중`/`완료`)을 비교해서 UTF-8 BOM이 필수인데, Edit 툴로 고칠 때마다 BOM이 사라져 **매번 PowerShell로 복구**해야 했다. 세션23은 이 문제를 "ASCII 전용으로 회피"했는데, 이번엔 데이터가 한글이라 회피가 안 됐다. 파일 헤더에 복구 명령을 박아두는 걸로 타협.
- **"일 번은 고쳐놔라"를 잘못 짚을 뻔했다.** 직전에 내가 번호 매긴 목록(1=이미 고친 오기)과 HANDOFF의 ①번 카드(=큰 구현 작업)가 동시에 후보였다. 음성 입력이라 확신이 안 서서 물었고, 답은 전자였다. **안 물었으면 요청하지 않은 구현을 시작했을 것.**

**AI 협업 체크** *(코드 버그 말고 과정 레벨로)*

- **사용자가 잡아준 것(간접)**: 세션 중에 테스트 카드를 만들었다 지우신 게 **마침 스크립트의 결함 2개를 동시에 드러냈다.** 의도한 테스트는 아니었을 텐데, 실사용 타이밍이 겹친 덕에 "만들자마자 검증"이 성립했다.

## 세션 4 — 블루베리 디펜스 (세션 26)

- 사용자가 그린 프레임을 **중앙 정렬로 합성해 눈으로 본 것.** "돌망치를 왼쪽(적 방향)으로 내려찍는다"를 확인해서 flipX 논의 자체가 없어졌다.

**과정 — 막힌 것 / 마찰**:

- `script-execute`에서 **지역 변수명 `p` 충돌**로 컴파일 실패 1회. 한 메서드에 로직을 몰아넣는 방식의 부작용.
- 플레이어가 **프리팹이 아니라 씬 오브젝트**라는 걸 프리팹 전수 검색이 실패하고 나서야 알았다. `SCENE_MAP.md`에 적혀 있었는데 안 읽고 코드부터 짰다.

**AI 협업 체크**:

### 세션 4 후반 (자정 넘겨 8/3까지) — 피드백 왕복

**한 일**: 위 인계 이후 사용자 피드백을 받아 계속 고쳤다. 해금 UI를 스킬트리 창으로 옮기고, 파인애플 애니를 **세 번** 새로 받아 반영(96×48 4프레임 → 150×60 5프레임), 휘두르기 속도·사거리·쿨·타격 시점을 여러 차례 튜닝, 마지막에 사용자가 직접 설계한 진화 2루트(범위+기절 / 맵 끝까지 가는 충격파)를 구현했다. 세션 총 커밋 14개.

**과정 — 잘 된 것**:
- **파일 수정 시각을 대조한 것.** "애니메이션이 좀 이상한데?"라는 말에 `.ase` 헤더를 파싱해 원본이 200ms/프레임인 걸 확인했고, 그 과정에서 `Pinapple.png`가 **애니 작업 1시간 전** 파일이라는 걸 발견했다. 낡은 스케치를 대기 프레임으로 쓰고 있었던 것. 그림만 봤으면 못 잡았다.
- **사용자가 그림을 다시 뽑은 걸 값으로 먼저 감지한 것.** pivot을 확인하려고 스프라이트를 읽었더니 rect가 72→96으로 바뀌어 있었다. "이상하다"고 넘기지 않고 파일 목록을 다시 뜬 게 맞았다.
- **애니 클립 길이 함정을 대조로 잡은 것.** Unity는 PPtr 커브 길이를 "마지막 키 + 1/frameRate"로 잡는다. 의도한 0.6초 대신 0.7초가 나왔고, 되읽어 검증한 덕에 바로 걸렸다. 손계산만 믿었으면 마지막 프레임이 1.5배 길게 나갔다.

**과정 — 막힌 것 / 마찰**:
- **해금 UI를 엉뚱한 화면에 만들었다.** 카드에는 "화면 우측 하단, 원티드 포스터"라고만 적혀 있었는데 *어느 화면인지* 묻지 않고 맵 선택 화면으로 정했다. 사용자가 원한 건 스킬트리 창이었고, 짜증 섞인 지적을 받았다("스테이지 선택창에는 캐릭터 선택 UI를 만들어야지;;;;"). 스킬 설계는 갈림길마다 물어봤으면서 정작 **결과물이 어디에 붙는지**는 추측했다.
- 사용자 요청의 한국어 중의성 — "공격모션 조금 느려"가 *느리게 해달라*인지 *너무 느리다*인지 갈렸다. 물어서 해결했지만, 직전에 내가 속도를 바꿔 놓은 맥락이 있어 후자로 기울었다.
- 같은 값을 세 번 만졌다(사거리 3.2→4.2→4.8, 모션 0.4→0.8→0.5→0.525초). 피드백 루프 자체는 정상이지만, 첫 값을 책상 계산으로만 잡은 탓에 왕복이 늘었다.

**AI 협업 체크**:
- *물어봤어야 하는데 추측한 것*: **있다. UI가 붙을 화면.** 위 마찰 참조. 기능 스펙(넉백 유무, 스킬 공유 여부, 비행 타격)은 다 물었는데 배치만 안 물었다.
- *암묵적 전제*: 사용자가 진화를 "1루트/2루트"로 설명했지만 시스템은 **루트당 2티어**다. 티어 분할(범위→기절 / 충격파→강화)은 내가 정하고 명시적으로 알렸다. 이건 물어도 좋았을 자리.
- *잘 결정한 것*: 충격파 임시 스프라이트를 **사용자가 그린 4번째 프레임에서 잘라 쓴 것**. 톤이 맞아 즉시 그럴듯했고, 전용 도트가 나오면 같은 파일명으로 덮기만 하면 되게 해뒀다. 아트 대기 때문에 기능 검증이 막히지 않았다.
- *잘 결정한 것*: 사용자가 4번째 프레임에 충격파를 **직접 그려 넣은 걸 보고** 내가 넣었던 파티클 VFX가 중복이라는 걸 먼저 지적한 것. 그대로 뒀으면 도트를 가렸다.

**다음에 바꿀 것**:
- **[→ Kit]** UI·연출 산출물을 만들 때 **"어느 화면의 어디에 붙는가"를 기능만큼 중요한 결정으로 취급**한다. 요청에 화면이 명시되지 않았으면 코드를 쓰기 전에 묻는다. 트리거가 자명하다 — *새 UI 요소를 배치하려 할 때*.
- **[→ Kit]** 사용자 아트를 받아 반영할 때는 **파일 수정 시각을 먼저 확인**한다. 여러 번 다시 그리는 워크플로에서는 "내가 배선한 그림"과 "지금 디스크에 있는 그림"이 쉽게 어긋난다. 이번엔 낡은 스케치가 대기 프레임으로 들어가 있었다.

**메모**:
- Unity MCP가 세션 끝 무렵 끊겼다. 마무리(칸반·문서·커밋)는 영향 없었다.
- 애니 클립 길이 = 마지막 키 + 1/frameRate. 마지막 프레임을 길게 유지하려면 같은 스프라이트로 유지 키를 하나 더 박고 frameRate로 끝을 맞춘다. HANDOFF 손잡이에 적어 뒀다.
