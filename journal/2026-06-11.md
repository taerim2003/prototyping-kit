## 세션 2 — OrganicFoodShop (농사 인터랙션 + 진행 시스템)

**목표**: P0 한 바퀴를 넘어, 마우스/핫바 기반 농사 인터랙션과 P1~P3 백로그 로직(레벨·해금·업그레이드·스킬·세이브) + 씨앗 상점 UI까지 한꺼번에 밀어붙이기.

**한 일**:
- 농사를 **타일 그리드 + 마우스/핫바**로 구현(GameObject Plot 폐기). FarmGrid·FarmMouseController·CellHighlighter·Hotbar(상태)·HotbarUI(UI Toolkit). 드래그 연속 작업, 휠/숫자키 선택, 수확물 슬롯, 물 자국 타원, 머리 위 수확 팝업까지.
- 진행 시스템 로직 일괄 작성: 작물 레벨/판매가, 2작물 해금 사슬(14종), 업그레이드, 스킬트리, 세이브(개발 중 off).
- 씨앗 상점을 UI Toolkit 창으로(작물당 오브젝트 → 단일 상점). ▶ 실제 플레이로 농사 루프 검증.

**과정 — 잘 된 것**:
- "코드 먼저 쭉 쓰고, 배선·검증은 유저가" 분업이 잘 굴러감. 컴파일 불가 환경이라 정적 작성 → 유저가 ▶로 즉시 피드백 → 빠른 반복.
- 버그를 추측으로 고치지 않고 **격리 실험**을 유저에게 부탁한 게 결정적이었음(빈 칸에 물 줘보기 → 물 타원이 작물에 가린 게 아니라 *가장자리 알파*가 원인임을 분리).

**과정 — 막힌 것 / 마찰**:
- **물 타원이 "안 보이는" 문제로 5~6턴 헤맴.** 색을 계속 진하게 바꿔도 그대로 → 원인이 `[SerializeField]` 필드라 **코드 기본값 변경이 씬의 기존 직렬화 값에 가려진 것**. 그동안 내 색 변경이 전부 무효였고, 정작 보이던 변화는 런타임 생성 텍스처의 가장자리뿐. 결국 가장자리 SmoothStep falloff가 거의 전부를 투명하게 만든 게 진짜 원인.
- UI Toolkit **폰트를 USS `-unity-font-definition: url(...)`** 로 박았다가 텍스트가 전부 사라짐 → 되돌리고 에디터(PanelSettings Theme)로 우회.
- `VisualTreeAsset.Instantiate()`가 TemplateContainer를 돌려줘서 선택 클래스가 안쪽 슬롯에 안 먹던 버그.
- CLAUDE.md §9의 일기 경로(`f:\...`)가 이 PC엔 없음 → 키트 위치(`d:\unity\prototyping-kit`)를 찾느라 탐색.

**다음에 바꿀 것**:
- **런타임에 자주 튜닝할 시각값은 `[SerializeField]` 대신 코드 상수로** 두거나, 굳이 직렬화하면 "코드 기본값 바꿔도 씬 인스턴스엔 반영 안 됨"을 즉시 의심할 것. 이번처럼 "바꿨는데 그대로"면 직렬화 shadowing부터 점검.
- **UI Toolkit 폰트는 처음부터 PanelSettings Theme(.tss)로.** USS url 방식 금지 — 키트 규칙에 메모할 만함.
- CLAUDE.md §9 경로를 실제 위치로 수정 필요(F:→D:).

**메모**:
- 수확물 진열 방식이 미결: 진열대가 고정 작물 자동충전 vs 핫바에서 든 수확물을 올리는 범용 진열대. 다음 세션 첫 결정.
- 세이브는 일부러 꺼둔 상태(`SaveSystem.Enabled=false`). 밸런싱 끝나면 켜고 FarmGrid 셀 상태 직렬화 추가.

## 세션 3 — OrganicFoodShop (상점 씬 완성 + 인터랙션 폴리시)

**목표**: P0 루프를 엔진에서 끝까지 검증하고(밭↔상점 한 바퀴), 상점 손님/진열대/씬전환을 실제로 돌게 만든 뒤 농사·상점 인터랙션 디테일을 다듬기.

**한 일**:
- **P0 한 바퀴 엔진 검증 통과** — 밭(심기·물·수확)→문→상점(진열·손님·돈)→문→밭. Build Settings 등록·씬 배선·Customer/Shelf/Hotbar 프리팹화 완료.
- 상점 코드 정리·확장: 진열대 자동등록(`Shelf.All`)으로 스포너 수동 리스트 폐기, 손님 **상태머신 + 웨이포인트 그래프(BFS) 보행**, 문 = **트리거 방식**, 손님/물주기 **애니 생성기**(에디터 메뉴), 진열대 아이콘+수량, 플레이어 기준 Y-깊이 정렬.
- 농사 인터랙션 디테일: 드래그 물주기 금지→**애니 시간으로 게이트한 홀드 물주기**, 심기 0.1s·수확 0.5s 딜레이, 사정거리 셀→**월드거리(float)**, 대각선 이동·물주기 = 좌/우 모션.

**과정 — 잘 된 것**:
- "정적 코드 작성 → 유저가 ▶로 즉시 검증 → 구체 피드백 → 반복" 분업이 이번에도 빠르게 굴러감. 한 메시지에 1~2개 작은 요청이 계속 들어와도 surgical 편집으로 대응됨.
- **설계 막다른 길을 빨리 인정하고 갈아탄 것**: 단방향 통로 웨이포인트가 "두 줄 진열대"에서 안 맞자 곧장 웨이포인트 그래프+BFS로 피벗. 우겨넣지 않은 게 좋았음.

**과정 — 막힌 것 / 마찰**:
- **유저 표현을 내가 오독해서 2~3턴 낭비.** "플레이어 이동이 안됨"을 WASD 이동으로 읽었는데 실제는 *씬간 이동(문)*이었음. 또 "인터랙션 범위"를 PlayerInteractor로 짐작했으나 실제는 CellHighlighter(밭 사정거리). → **어느 컴포넌트/맥락인지 먼저 1줄 확인**했어야.
- 처음에 손님 경로를 단방향 리스트로 과소설계 → 두 줄 레이아웃에서 재작업. 레이아웃 전제를 먼저 물었어야.
- 월드 텍스트(진열대 수량)에서 유저가 UGUI TMP를 붙여 Canvas가 딸려옴 → 3D TMP로 안내. 처음부터 "월드 = 3D TextMeshPro"를 명시했어야.

**다음에 바꿀 것**:
- **버그/요청 받으면 고치기 전에 "어느 씬/어느 컴포넌트/어떤 입력인지" 한 줄로 되묻기.** 이번 오독들은 전부 이 한 줄로 예방 가능했음.
- 공간 로직(경로·정렬·범위)은 **레이아웃 전제를 먼저 확정**하고 짜기. "줄이 몇 개냐, 입출구가 같냐"를 코드 전에.

**메모**:
- 기본 피쳐(밭·상점·이동·인터랙션) 일단락. **내일부터 발전(progression) 피쳐**: 업그레이드·작물레벨·해금·스킬트리. 로직은 대부분 이미 있음(`CropProgression`/`UpgradeState`/`Upgrade`/`SkillTree`+`skills.json`) → 배선·UI·밸런싱이 핵심.
- 세이브 여전히 off(`SaveSystem.Enabled=false`) + FarmGrid 셀 직렬화 미구현. 진행 피쳐 붙이며 같이 켤지 결정.
