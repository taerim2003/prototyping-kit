**AI 협업 체크**:

**다음에 바꿀 것**:

## 세션 66 — BlueberryDefense (밸런스 수치 · 호밍 직진 · 스킬트리 구조·가격 재구성, 9/15 새벽까지)

**목표**: 사용자가 연달아 던지는 소규모 요청 처리 → 중간부터 "은별–금별 4링크 떨어뜨리기"가 스킬트리 전체 재설계로 번졌다.

**한 일**: 산탄·독수리·오브·화살 수치 조정, 호밍 미사일 "절대 멈추지 않음", 스킬트리 비행·보스 아이콘 배선.
스킬트리는 네 번 갈아엎었다: ① 은별 줄 세우기(사용자 격노 — 롤백) ② PoE식 방향 조사·계획 승인 → 대역 곱셈 가격 + 부유 노드 벽 + 8가지 일렬 복도 ③ "쭉쭉 뻗고 한 길로만"
→ 규칙을 벌점으로 둔 담금질 탐색으로 가지 많은 트리 + 선 길이 1 촘촘한 배치 ④ 화살·휘두르기·진화 위치 조정은 "바뀐 부모 수 벌점" 탐색으로 최소 변경.
가격은 시뮬레이터로 대역 벽을 재서 골랐다(대역 곱 ×4, 해금 60%). 세이브 초기화, 설계 문서 삭제(사용자 요청).

**과정 — 잘 된 것**:
- 검사기를 먼저 만들고 **대조군(일부러 망가뜨린 설계)** 으로 살아 있는지 확인한 뒤 적용 — 적용 후 규칙 위반 0이 매번 숫자로 나왔다.
- 가격을 감이 아니라 모의 진행("k+1대역이 판 몇 번인가")으로 정해 설명이 짧았다. 사용자는 수치엔 이의 없이 구조·위치만 고쳤다.
- 제약 탐색(담금질)으로 바꾸고 나서 "이 조건 추가"가 벌점 한 줄로 끝났다 — 손으로 짠 틀은 조건 하나에 통째로 무너졌다.

**과정 — 막힌 것 / 마찰**:
- **요청 범위를 스스로 부풀렸다.** "은별·금별만"을 받고 일반 노드가 종류별 체인이어야 한다고 전제 → 트리 전체를 재배치. 사용자 "제정신이니 … 은별이랑 금별만 조정하라고 했잖아".
- **모양을 규칙 수치로만 판정했다.** 겹침·교차 0을 통과했다고 좋은 지도라 여겼는데 사용자 눈엔 "쭉쭉 뻗은 복도". 캡처는 적용 *뒤에* 봤다.
- 탐욕 생성기 → 막힘 → 순서 바꾸기 → 막힘을 네 바퀴 돈 뒤에야 담금질로 갈아탔다. 제약이 서로 얽힌 배치 문제면 처음부터 탐색으로 갔어야 했다.
- MCP 호출 한도(수 초)에 걸려 "Response data is null"을 여러 번 봤다 — 긴 탐색은 호출을 쪼개 static 상태로 이어 붙였다(재컴파일하면 날아가서 한 번 다시 돌렸다).
- 노션 쓰기에 한글을 또 `\u` 이스케이프로 넘겼다(세션 65에 이어 두 번째). 되읽기 단계 덕에 깨진 글자는 없었다.

**AI 협업 체크**:
- 추측으로 진행: 독수리 "5타×3"을 투하 5회로 · 화살 데미지를 타당으로 · 가지 짝 조합 · 대역별 은별/금별 가격대 · 화살 "100원 정도"를 대역 2(80)로 — 확인 대기에 기록.
- 사용자가 짚어 준 것: 일반 노드는 흩뿌리는 길 · 가지 수(자식 2~3) · 4링크는 절대 조건 아님 · 해금 30%→고정 30→60%로 두 번 번복 · 모양은 촘촘하게.
- 잘 한 것: 계획을 실행 전에 조사(PoE·인크리멘탈)와 함께 내놓아 방향 승인을 받았고, 가격 유도라는 사용자 아이디어를 시뮬레이터로 바로 검증했다.

**다음에 바꿀 것**:
- 새 규칙 없음. 도메인 교정(일반 노드=길, 가지 치기, 가격 유도)은 메모리 `skilltree-normal-nodes-are-scattered-paths`에 남겼다.
- 배치·지도처럼 **눈으로 판정되는 산출물은 적용 직후 캡처를 첫 보고에 붙인다** — 이번엔 매번 그렇게 해서 사용자가 바로 교정할 수 있었다(유지).
