## 세션 1 — 블루베리 디펜스: 밸런스/UI 다듬기 연속 요청 + 리팩토링 마무리

**목표**: 리팩토링 로드맵이 끝난 뒤, 사용자가 실플레이 중 발견한 자잘한 요청을 하나씩(종이비행기 스테이지·호밍 아이콘·레벨업 대체보상·패시브 데이터화·낙뢰 표시버그·일시정지 2열 개편) 처리.

**한 일**:
- 6건 처리 + HANDOFF 린화. 종이비행기 전용 스테이지를 코드 하드코딩(`==7`)에서 StageTable 데이터로, 레벨업 대체선택지(LevelUpStatOptionSO)를 정수 보상으로 교체하며 SO·타입·문서까지 정리, 패시브를 액티브와 대칭인 `PassiveProgression` SO로 이관.
- 낙뢰 일시정지 표시 음수 버그를 "실제 피해가 아니라 `GetDefaultDamage`가 실시간 ProcDamage를 기준값으로 반환한 표시 버그"로 규명·수정.
- 일시정지 창을 단일 텍스트 → 2열(액티브/패시브) + 스킬 아이콘 레이아웃으로 재작성.
- 전부 assets-refresh+Error로그로 컴파일 검증. 패시브 에셋 생성·씬 배선은 script-execute로 SampleScene을 **additive로 열어** 처리(열려 있던 Title 씬 안 건드림).

**과정 — 잘 된 것**:
- **읽어서 원인부터 못박음.** 종이비행기는 grep로 `==7` 하드코딩을, 낙뢰는 DescribeLevelUpGains→GetDefaultDamage 체인을 따라가 "표시 버그(부호 역전)"임을 수치(12·17.2)로 재구성. 추측 없이 코드 근거로.
- **사용자의 단순화 제안에 함정을 짚음.** "종이비행기 확률 1로 하면 똑같잖아"에 else-if 순서상 elite가 먼저 굴려져 30% 섞인다는 걸 지적하고 elite/shield도 0으로. 그대로 했으면 "종이비행기만"이 안 됐다.
- **파괴적 정리 전에 고아 표면화·확인.** LevelUpStatOptionSO 제거가 대시보드·SO 3개·문서를 고아로 만든다고 먼저 보고 → 사용자 "정리해" 후 삭제. 되돌리기 큰 삭제를 침묵 진행 안 함.
- **비파괴 배선.** 패시브 SO를 안 열린 SampleScene에 넣을 때 additive open→SerializedObject 배선→save→close로, 사용자가 보던 Title 씬을 유지. 씬 YAML 손편집 대신 Unity가 GUID/직렬화 처리.

**과정 — 막힌 것 / 마찰**:
- **🟡 씬에 같은 필드명이 둘.** 호밍 아이콘 `activeIcons[6]`가 LevelUpUI·HUDController 두 컴포넌트에 있고, 각 배열의 index 6·8이 같은 플레이스홀더라 단순 치환이 4곳에 걸렸다. 앞뒤 줄 포함한 3줄 블록 + replace_all로 index 6만 정확히 겨냥. 씬 YAML 직접 편집은 항상 "이 필드가 유일한가" 먼저 확인해야.
- **🟡 script-execute 컴파일 스냅샷이 낡음.** const 추가 직후 refresh에서 `CS0103 EssenceReward 없음`이 떴는데 파일엔 있었음 — 이전 편집 중간 스냅샷을 컴파일한 것. ForceUpdate 재refresh로 사라짐. Error로그 1건은 재refresh 후 재확인이 안전.

**AI 협업 체크**:
- 추측으로 진행? — 안 함. 낙뢰·종이비행기 둘 다 코드 읽어 원인 확정 후 손댐. 패시브 배선도 씬 YAML에서 guid 대조로 검증.
- 암묵 전제? — 패시브 데이터화 **범위**(선형 진행만 vs 진화 트리까지)와 크리/초기화 기본값 처리(SO 완전이관+판마다 리셋)를 AskUserQuestion으로 못박음. 안 물었으면 진화 트리 수십 값까지 손대거나 리셋 없이 누적버그를 남길 뻔.
- 자율 결정 잘한 것 — elite 순서 함정 지적, 고아 표면화, additive 배선, 낙뢰 표시 vs 실피해 구분. 재현할 것.
