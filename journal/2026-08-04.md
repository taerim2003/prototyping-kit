**과정 — 잘 된 것**:
- **대조군을 넣은 검증이 실제로 여러 번 걸러냈다.** 미리보기 첫 배치는 카드 밖으로 33px 나갔는데 대조군이 `insideCard=False`로 잡아줬고, 이징은 easeIn 대조군이 `frontLoaded=False`로 나와 검사가 살아 있음을 보여줬다. "전부 통과"만 봤으면 못 믿었을 것.
- **씬 수치를 실측하고 나서 배치를 정했다.** 설명 박스가 90px인데 한 줄 텍스트는 37px(TopLeft)이라 바닥 53px가 빈다 — 이걸 재고 나서야 올바른 위치가 나왔다. 추측으로 짰으면 두 번 고쳤다.
- **넉백을 값이 아니라 원인으로 접근했다.** "속도 올려주세요"에 상수만 만졌으면 떨림은 그대로였을 것.

**과정 — 막힌 것 / 마찰**:
1. 🔴 **UI 세로 전환의 범위를 통째로 잘못 잡았다.** 사용자는 "레벨업 또는 진화 둘 중 선택하는" **갈림길 하나**를 말했는데, 나는 "레벨업/진화 선택지 UI"를 *선택지 UI 전체*로 읽고 **씬의 카드 3장을 다 고쳐 저장**했다. 되돌리고 재작업.
   → `LevelUpUI` 하나가 **세 화면**(레벨업 3택 / 갈림길 2택 / 진화 대상 선택)을 그린다는 걸 알고 있었는데도, "어느 화면인가"를 안 물었다.
2. 🔴 **`optionOutlines`를 "미배선"으로 오판해 사용자에게 보고했다.** 에디트모드에서 `null`이라 배선 누락이라 결론지었는데, 실제로는 `Awake`에서 코드로 만드는 배열이라 런타임엔 정상이다.
   → **`unity-mcp` 스킬에 "에디트모드에서 런타임 필드를 읽어 검증하지 말 것"이라고 적혀 있는데도 어겼다.** 읽고도 어긴 케이스.
3. **"진화 아이콘 가시성"을 진화 *카드* 강조로 오해**했다. 사용자가 두 번 되짚어 준 뒤에야 조합 미리보기 아이콘 얘기인 걸 알았다.
4. `unity-mcp` 스킬을 세션 중반에야 열었다 — `script-execute`를 이미 여러 번 쓴 뒤였다.

**AI 협업 체크** *(코드 버그 말고 과정 레벨로)*:
- **물어봤어야 하는데 추측**: UI 세로 전환의 대상 화면. 마찰 1이 그대로 이 항목이다. 기능(세로로, 아이콘 아래) 은 명확했고 **대상만** 모호했는데, 그 하나를 안 물어서 씬을 고쳤다 되돌렸다.
- **유저가 명시했어야 했던 것**: 딱히 없다. 되짚어 보면 첫 요청에도 "그 보물상자때 등장하는 UI"의 의도가 읽힌다 — 내가 넓게 읽은 쪽이다.
- **잘 결정한 것**: 넉백을 원인 규명으로 접근한 것, 매 검증에 대조군을 넣은 것, 씬을 고치지 않고 코드 전환/복원으로 갈림길 레이아웃을 만든 것(되돌리기가 공짜가 됐다).

**다음에 바꿀 것**:
- **[→ Kit] "UI를 고치기 전에 그 코드가 그리는 화면을 열거한다."**
