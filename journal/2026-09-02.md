## 세션 2 — 블루베리 디펜스 (세션 55)

**목표**: Unity CLI를 우리 프로젝트에 적용할 수 있는지 검토 — 기존 Unity-MCP 대체 가능성을 시간·정확도·토큰 관점에서.

**한 일**: 게임 코드는 한 줄도 안 건드렸다. Unity CLI의 실체를 확인하고(1st-party, `com.unity.pipeline`이 에디터 안에
로컬 HTTP 서버를 띄우는 구조), **38개 세션 트랜스크립트를 직접 세서** 우리 MCP 사용 프로필을 실측했다 —
`script-execute`가 2003건 중 1580건(79%)이고, 보낸 C# 코드가 Unity 관련 토큰의 74%(576k). 결론은
**"지금 프로토타입은 MCP 유지, 다음 프로토타입 세션 0에서 CLI 우선"**. 킷 `templates/CLAUDE.md` §6과
`SESSION_ZERO.md`, 프로젝트 `HANDOFF.md`에 각각 반영(사본이 아니라 실체 1곳 + 포인터 2곳).

**과정 — 잘 된 것**: **"값을 먼저 재 본다"가 결론을 두 번 뒤집었다.** ① 트랜스크립트를 세기 전엔 "타입 툴 40개를
갈아타야 한다"고 봤는데, 실제로는 우리가 쓰는 게 사실상 `eval` 하나였다. ② 토큰도 마찬가지 — 실측 없이 갔으면
"CLI가 토큰을 아낀다"는 홍보 문구를 그대로 옮겼을 것이다. 재보니 비용의 대부분이 **내가 보내는 C# 코드**라
전송 계층을 바꿔도 안 줄어든다. 로컬 확인(설치 여부·훅·스킬 크기)을 웹 조사와 같은 턴에 병렬로 돌린 것도 빨랐다.

**과정 — 막힌 것 / 마찰**:
- 유니티 공식 문서가 WebFetch에 네비게이션만 주고 본문을 안 내줘서 3번 헛돌았다. 명령 전수 목록은 결국
  커뮤니티가 만든 스킬 문서(GitHub raw)가 가장 정확했다. **공식 문서가 SPA면 raw 마크다운을 먼저 찾는 게 빠르다.**
- `python`이 Windows Store stub이라 첫 계측이 빈손으로 돌아왔다(출력이 `Python` 한 줄). node로 갈아타서 해결.

**AI 협업 체크**:
- **축을 의심하지 않고 성실히 쟀다 — 이번 세션 최대 실수.** 사용자가 준 세 축(시간·정확도·토큰)으로 재니
  대부분 무승부가 나왔고, 나는 그걸 "우수한 점이 거의 없다"로 요약했다. 사용자가 *"정말 우수한 점이 거의 없는거야?"*
  라고 되물어서야 플레이모드 제어·Undo 묶기·헤드리스 컴파일이 서드파티 MCP엔 **아예 없는 기능**임을 확인했다.
  **축이 모자랐던 것이지 CLI가 별로였던 게 아니다.**
- **추측으로 진행한 것**: "Unity CLI"가 뭘 가리키는지 안 묻고 웹에서 찾았다. 이번엔 맞았지만 사내 스크립트를
  가리켰다면 통째로 헛일이었다. 다만 찾는 비용이 묻는 비용보다 쌌고, 찾자마자 **실체부터 보고**한 순서는 맞았다.
- **잘 결정한 것 둘**: ① 사용자 표현("MCP를 대체")을 그대로 받지 않고 **구조가 포함 관계임을 먼저 정정**한 것.
  ② 킷에 규칙을 넣을 때 **"속도·토큰은 근거가 아니다"를 명시적으로 적어둔 것** — 틀린 근거로 다시 갈아타자는
  말이 나오는 걸 막는다.

**다음에 바꿀 것**:
- **[→ Kit] 사용자가 평가 축을 지정해 주면, 재기 전에 "이 축들로 안 잡히는 게 있나"를 한 번 본다.**
  지정된 축만 성실히 재면 결론이 "차이 없음"으로 나오고, 그게 **"가치 없음"으로 잘못 요약된다.**
  트리거 자명 — *사용자가 "A·B·C 관점에서 봐줘"라고 축을 나열하는 순간.*
  → 프로젝트 `CLAUDE.md` §1과 키트 `templates/CLAUDE.md` 둘 다에 넣었다.

**메모**: Unity CLI·`com.unity.pipeline`은 둘 다 experimental(0.4.0-exp.1)이다. 다음 프로토타입 착수 때
`unity --help`와 `unity command`로 능력을 **직접 다시 확인**해야 한다 — 이번에 정리한 목록은 그때 낡아 있을 것이다.

- **인자 크기 한계를 두 번 만났다.** 유니코드 이스케이프가 바이트를 두 배로 키워 9.8KB에서 잘렸다.
  한글을 그대로 넣으니 통과했다 — 규칙을 지켰으면 겪지 않았을 일이다.

**AI 협업 체크** *(코드 버그 말고 과정 레벨로)*:
- **잘 결정한 것**: 죽은 코드를 지우기 전에 **무엇이 죽는지 세어서 보고**한 것. 건강 패시브의 체력 재생처럼
  "있는 줄 알았던 기능"이 사라지는 게 넷이었고, 그건 사용자가 알아야 할 사실이었다.
- **물어봤어야 하는데 추측으로 간 것**: 포도 진화체 2차 이름(역병/마비 포도알)을 내가 지었다.
  기획안엔 1차 이름만 있었다. 초안이라 밝혔지만 한 줄 물어도 됐다.
- **유저가 명시했어야 했는데 넘어갈 뻔한 전제**: `Grape1~5`가 Idle인지 Attack인지. 파인애플은
  `Pinapple.png`(48×48)와 `Pinapple1~5`(150×96)가 다른 용도였는데 포도는 48×48 5장뿐이라 그림으론 안 갈렸다.
  물어서 "1이 Idle, 1~5가 공격"으로 확정했다 — 안 물었으면 Idle이 없는 캐릭터가 됐다.

**다음에 바꿀 것**:
- **[→ Kit] 스프라이트를 배선하고 "값이 맞다"로 끝내지 말 것 — 같은 그림의 사본이 여러 계통일 수 있다.**
  라이브러리 하나만 고치고 화면을 안 봤으면 못 잡았다. `unity-mcp` 스킬 9-1("값이 다 맞는데 화면이 틀릴 수 있다") 옆에 붙였다.
- **외부 도구에 한글을 넘길 때 이스케이프를 만들지 않는다** — 이미 규칙에 있는데 크기를 줄이려다 어겼다.
  크기가 문제면 **나눠 보내는 게 답이지 이스케이프가 아니다**(이스케이프는 오히려 두 배가 된다).

## 세션 4 — 블루베리 디펜스 (병렬 세션, 게임 코드 무변경)

**목표**: `/loop`과 `/schedule`이 뭔지 설명하기.
진행 중 **"어제 자동 이어하기가 왜 안 돌았나"** 규명과 밤샘 무인 운전 절차 확립으로 옮겨갔다.

**한 일**:
- 두 명령의 경계를 갈랐다. `/loop`은 로컬 세션(고정 간격=CronCreate / 동적=ScheduleWakeup / 프롬프트 생략=`.claude/loop.md`),
  `/schedule`은 클라우드 루틴. **클라우드 루틴은 로컬 MCP를 못 써서 이 프로젝트엔 거의 쓸 데가 없다**(Unity MCP가 `localhost`).
- **자동 이어하기 실패 원인을 트랜스크립트로 확정했다.** 17:18:51.781 `enqueue` → .785 `dequeue` → 17:18:52 `429`.
  **733ms 만에 끝났다.** 큐는 "한도 풀릴 때까지 보관하는 통"이 아니다. 19:50 리셋 시각엔 continuation 프롬프트가
  아예 없다 — armed 대기가 폰에서 보낸 메시지 하나로 `manual_submit` 종료됐다.
- `~/.claude/settings.json`에 `autoContinueAtUsageLimit: true`를 명시(계정 조회 실패 시 OFF로 떨어지는 경로 제거).
- `.claude/loop.md` 작성 — 칸반 드레인 태스크 + **종료 조건 4겹**.

**과정 — 잘 된 것**:
- **문서가 없어서 CLI 바이너리 문자열을 팠다.** 상태 머신(`sleptThroughReset`·`manual_submit`),
  상수(`recurringMaxAgeMs`·keepalive 예산 `F=1`), 텔레메트리 이름까지 나왔다. 추측할 자리가 크게 줄었다.
- **마지막에 추측을 멈추고 로그를 열었다.** 가설 세 개가 서로 안 갈렸는데 트랜스크립트 한 줄이 즉시 갈랐다.
  더 일찍 열었어야 했다.

**과정 — 막힌 것 / 마찰**:
- 🔴 **불가능한 절차를 제시했다.** "한도에 걸린 뒤 폰에서 cron 예약을 걸어라"고 단계를 써 놨는데,
  **예약을 부탁하는 그 메시지 자체가 429로 죽고 배너도 취소시킨다.** 1번 단계가 그 상황에서 칠 수 없는 것이었다.
  사용자가 *"이게 한도 히트를 친 상황에선 Cron 예약을 걸 수 없다는 거야?"* 라고 되물어서야 봤다.
- 🔴 **내가 만든 `loop.md`가 영원히 도는 물건이었다.** "노션 카드 상태 변경 금지" + "To Do가 비면 종료"를
  같은 파일에 나란히 적었다 — 상태를 안 바꾸니 To Do는 **절대 안 빈다.** 게다가 매 틱 "맨 위 카드"를 집어
  같은 카드를 무한 반복한다. 사용자가 *"계속 돌까봐"* 라고 걱정해서야 읽어봤다.
- **정정을 두 번 했다.** `graceMs 90초`(실은 jitterMax였다) → 30분, "동적 모드 즉사" → keepalive 1회 유예.
  둘 다 바이너리를 급하게 읽어 옆 상수를 집은 것이다.

**AI 협업 체크** *(코드 버그 말고 과정 레벨로)*:
- **물어봤어야 하는데 추측으로 간 것**: 원인을 `sleptThroughReset`(PC 절전)으로 지목하고 전원 설정까지 실측했다.
  **"이 PC 24시간 켜두시나요"** 한 줄이면 그 단계를 통째로 건너뛰었다. 사용자가 운영 환경을 말해주자 즉시 폐기됐다.
- **유저가 명시했어야 했는데 넘어간 전제**: 24시간 가동 + **Remote Control로 폰에서 조작**.
  이게 처음부터 있었으면 진단이 세 턴 짧았다.
- **잘 결정한 것**: 문서에 없는 걸 "모른다"로 끝내지 않고 바이너리·트랜스크립트라는 **1차 자료**로 간 것.
  그리고 확인 못 한 것(Esc가 고정 간격 루프까지 죽이나)을 **미확인이라고 표시해 남긴 것.**

**다음에 바꿀 것**:
- **[→ Kit] 절차를 제시하기 전에 1번 단계가 그 상황에서 실행 가능한지 본다.** 막힌 상황을 벗어나는 절차일수록
  1번이 이미 막혀 있다. 템플릿 §1 + 프로젝트 CLAUDE.md §1 둘 다 반영.
