## 세션 1 — 블루베리 디펜스 (세션38, 스킬 이펙트 쪽 / 8-11 밤부터 이어짐)

**목표**: "나 스킬 이펙트 다 그린것같거든. 한번 쭉 확인해볼래? 빼먹은거 있으면 알려주고."

**한 일**: 노션 「아트 리소스 제작」·「스킬 리소스 확충」의 명세와 디스크의 `Effect_*` 파일을 대조해 누락을 보고하고,

신규 스크립트 3개(`RiseFade`·`RockDebris`·`StormCloudAura`), 신규 프리팹 11개.
휘두르기 **노란 범위 사각형을 걷어내고** 그 자리를 "맞은 적한테서 튀는 돌조각"으로 바꿨다(사용자 요청).

**과정 — 잘 된 것**:
- 🔴 **배선 전에 명세와 파일을 대조한 것.** 사용자는 "다 그렸다"고 했지만 체크 안 된 항목이 남아 있었고,
  그중 **「조준선/감시탑」은 사용자가 "뭐하라는건지 모르겠음"이라고 적어둔** 자리였다. 대조를 안 했으면 그냥 넘어갔을 것이다.
- 🔴 **"한 파일 = 한 그림인가"를 매번 확인한 것**(`unity-mcp` 스킬 규칙). 사용자 아트가 Unity 기본값(Multiple)으로 들어와
  **총 6장이 실제로 조각나 있었다**(`Effect_BigHammer5`는 4조각). 그대로 배선했으면 망치 대신 꼬리 조각만 날아갔다.
  게다가 아트를 다시 그려 덮어쓴 뒤에도 **한 번 더** 확인해서 재발 여부를 봤다.
- 🔴 **판정이 안 바뀐다는 걸 값으로 증명한 것.** 미니 회오리 전용 그림이 48px(본체 64px)이라 그냥 쓰면 작아지는데,
  scale 1.333× + 콜라이더 0.75×로 상쇄해 **스프라이트 월드 높이 3=3, 콜라이더 1.5=1.5**를 되읽어 확인했다.
  "그림만 갈아끼웠으니 밸런스는 그대로겠지"로 넘어갔으면 조용히 판정이 바뀌었을 자리다.
- **검사가 살아 있는지 대조군으로 확인한 것.** 임포트 정규화가 `changed=0`을 뱉었을 때 그대로 믿지 않고
  `UI_*`/`Panel*`을 같은 검사에 넣어 **14건이 BAD로 잡히는 것**을 보고서야 "정말 이미 정상"이라고 판단했다.
- **`ObjectPool.Despawn`에 중복 방지가 없다는 걸 배선 중에 발견한 것.** 플립북 자동반환과 호출측 타이머가 겹치면
  같은 오브젝트가 큐에 두 번 들어간다. 폭발만 호출측 방식으로 맞췄다.
- **플레이모드 가드를 스크립트 첫 줄에 넣어둔 것.** 사용자가 세 번 게임을 켰고 그때마다 씬 작업이 **자동으로 중단**됐다.
  없었으면 플레이 중 씬 수정이 통째로 날아가고 원인도 몰랐을 것이다.
- **되돌리기 전에 백업부터 뜬 것.** 사용자가 파인애플 원본을 잃고 revert를 요청했을 때, 오늘 그린 것을 먼저 스크래치패드에 복사한 뒤 되돌렸다.

**과정 — 막힌 것 / 마찰**:
- 🔴 **일괄 정규화가 남의 pivot을 깨뜨렸다.** `Effect_*` 전체에 `spriteAlignment = Center`를 밀어넣었는데,
  `Effect_BigTornado` 4장은 **바닥중앙 pivot(alignment 9)** 이 의도였다. 세로 213px짜리라 화면에서 **5유닛** 어긋난다.
  더 나쁜 건 **발견 경위**다 — 배선 검증이 아니라 `/wrap`의 `git diff`를 훑다가 우연히 봤다.
  내 검증은 전부 "내가 의도한 필드"만 확인했고 **의도하지 않은 필드가 같이 바뀐 건 안 봤다.**
- **플레이모드 충돌 3회.** 사용자가 결과를 보려고 게임을 켜는 것과, 내가 씬을 고치는 것이 계속 부딪쳤다.
  중간에 "망치가 아예 안보여"라는 말을 들었는데 **아직 배선을 못 한 상태**였다 — 진행 상황을 내가 제때 말하지 않아서 생긴 오해다.
- **캔버스 크기 변경의 파급을 미리 못 짚었다.** 파인애플이 150×60 → 150×96이 되면서 중앙 pivot 기준 몸이 0.84유닛 떠오르는데,
  이건 계산해서 알려주긴 했지만 **사용자가 그림을 다 그린 뒤**였다. 캔버스를 바꾸겠다고 할 때 짚었어야 했다.

**AI 협업 체크** *(코드 버그 말고 과정 레벨로)*:
- **추측으로 진행한 것 — 되감기 3세트의 루트 대응.** 사용자가 *"Yellow가 진화 루트 1, R*가 진화 루트 2일걸"* 이라고
  **"일걸"을 달아** 답했는데 그대로 배선했다. 그림만으로는 안 갈리는 자리라 물었어야 했다(세션35 접미사 함정과 같은 종류).
  다행히 코드 한 줄만 바꾸면 되는 자리이긴 하다.
- **사용자 질문이 사고를 막아준 것 — "원래 5프레임이었나?"**
  공격 클립이 5프레임인데 사용자가 4장만 다시 그린 걸 발견해 물었더니, 되돌아온 게 이 질문이었다.
  덕분에 **`Pinapple.ase` 작업 파일까지 덮어써진 상태**라는 게 드러났고 png만 골라 복원했다.
  내가 "5번 프레임만 망치 레이어를 비우자" 같은 우회로 밀었으면 원본은 영영 못 찾았을 것이다.
- **사용자가 끊어준 것 — "아니 ASE는 리버트하지 마."** 이미 png만 되돌린 뒤였지만, 사용자가 불안해할 만큼
  **내가 뭘 되돌릴지 먼저 선언하지 않았다.** 백업은 떴는데 "무엇을 되돌리고 무엇은 남기는지"를 실행 전에 한 줄로 말했어야 했다.
- **자율적으로 잘 결정한 것** — 산탄 알 프리팹이 추적 오브와 **공유**되고 있다는 걸 `grep`으로 먼저 확인하고,
  프리팹을 새로 만들어 원본을 안 건드리는 쪽을 골랐다. 그냥 스프라이트를 갈아끼웠으면 오브 R1까지 산탄 알이 됐다.

**다음에 바꿀 것**:
- **[→ Kit] 일괄 임포트 정규화는 "전체 공통인 것"만 건드린다.** `spriteMode`·PPU·filter는 프로젝트 규칙이라 전 파일 공통이지만,
  **pivot/alignment는 스프라이트마다 의도가 다르다**(바닥중앙으로 맞춰둔 세로로 긴 이펙트가 있다).
  트리거 자명 — *`TextureImporterSettings`의 필드를 루프로 덮어쓰려는 순간.* 건드릴 필드를 열거하고 **거기 pivot 계열이 있으면 뺀다.**
- **[→ Kit] 일괄 수정 뒤에는 `git diff`로 "안 건드리려던 파일"을 확인한다.** 되읽기 검증은 *내가 의도한 필드*만 보므로
  **의도하지 않은 변경을 구조적으로 못 잡는다.** N개 파일을 한 번에 고쳤으면 `git status`에 뜬 줄 수가 예상과 맞는지 본다.
- **씬을 고치기 전에 플레이모드를 확인하고, 막히면 즉시 사용자에게 알린다.** 조용히 대기하면 사용자는 "왜 안 되지"라고 생각한다.

**메모**: 병렬 세션(타이틀 UI·폰트)이 계속 돌았고, 이번엔 그쪽이 `HANDOFF.md`에 **내 파일 목록을 미리 갈라 적어둬서**

## 세션 2 — 블루베리 디펜스 (세션38, 타이틀 UI·폰트 쪽 / 8-11 낮부터 이어짐)

**목표**: "UI 자잘한거 할거야." — 폴리싱 9건으로 시작했는데 **폰트 아웃라인 왕복이 세션의 절반**을 먹었다.

**한 일**: 버튼 dim 연출(전 버튼) · 흰 박스를 블루베리 색으로 통일 · 카드 테두리/꺾쇠/이름표 · 캐릭터 카드 공격 모션 ·
3번 캐릭터 슬롯(잠김) · 맵 카드 배경 애니 · 커서 2배 · 벽지 무압축 · 캐릭터 헤더가 화면 밖으로 빠지던 버그 ·
**폰트 아웃라인 전면 재설계**(아틀라스 padding 9→20 재생성) · 에디터 도구 1종 신설.

**과정 — 잘 된 것**:
- **원인을 묻는 질문에 대조 실험으로 답한 것.** 사용자가 *"근데 두께를 키우면 왜 회색박스가 나와?"* 라고 물었을 때,
  같은 값으로 **15pt 한글 / 15pt 영문 / 30pt 한글** 세 줄을 한 화면에 렌더했다. 한글 15pt만 박스가 났다.
  값이 아니라 **글자 모양과 렌더 크기**가 원인이라는 게 그 한 장으로 갈렸다. 앞서 두 번 틀린 설명을 했던 터라 이게 유일하게 확실한 길이었다.
- 🔴 **"방법 없나?"에 전수 조사로 답한 것.** `WhitePurple`을 쓰는 텍스트 18개를 크기별로 세어 보니
  **12개가 27~48pt**였다. 즉 나는 **15pt 하나 때문에 전역 값을 깎아** 큰 글씨 12개를 손해 보게 하고 있었다.
  "한계다"라고 말할 뻔한 자리에서 조사 한 번이 답을 줬다.
- **화면 판정에 크롭+확대를 도입한 것.** 1920×1080 스크린샷으로는 1픽셀 아웃라인을 판정할 수 없다.
  PowerShell + `System.Drawing`으로 관심 영역만 5~6배 최근접 확대해 읽었더니 **회색 박스·안쪽 침범이 눈으로 갈렸다.**
- **아트 의존 값을 도구로 만든 것.** 파인애플 공격 캔버스가 150×60 → 150×96으로 바뀌어 구워둔 보정값이 어긋났는데,
  **같은 계산을 이번 세션에만 두 번** 했다. 두 번째에 `CharacterCardFraming` 에디터 메뉴로 만들었다.
  딸기가 대조군이다 — 캔버스가 같아 `scale 1 / offset 0`이 나와야 하고, 실제로 그렇게 나온다.

**과정 — 막힌 것 / 마찰**:
- 🔴 **폰트 아웃라인에서 사용자를 네 번 왕복시켰다.** 얇다 → 두껍게 → 안쪽 침범 → 더 두껍게 → 30% 깎기.
  근본 원인은 **한 번에 한 손잡이만** 보고 움직인 것이다. `_FaceDilate`와 `_OutlineWidth`는
  "바깥 번짐"과 "안쪽 침범"이라는 **두 결과의 공통 입력**인데, 매번 하나를 고치고 다른 하나가 터지는 걸 뒤늦게 봤다.
  두 수식을 세우고 나서야 왕복이 멈췄다 — **수식을 먼저 세웠어야 했다.**
- 🔴 **틀린 설명을 두 번 확신 있게 했다.** ① "실효 합이 0.5를 넘어 패딩이 칠해진다" ② "padding을 늘려도 비율이라 소용없다".
  둘 다 손계산만 하고 실측을 안 했다. 특히 ②는 **정답을 스스로 막았다** — 그 판단 때문에 padding 20 실험을 두 턴 늦게 했다.
  사용자가 *"아니 방법 없어?"* 라고 밀어붙이지 않았으면 안 갔을 길이다.
- **맵 카드에 "같은 증상"이라고 잘못 보고했다.** 맵 카드에는 `BackLine`(1.04배 바깥 테두리)이 있어 원래부터
  그림이 테두리를 안 넘고 있었는데 캐릭터 카드와 같은 구조라고 단정했다. 그 보고 때문에 사용자가 "맵도 해줘"를
  요청했고, 넣자마자 테두리가 두 겹이 됐다. **구조가 같다고 말하기 전에 자식 목록을 봤어야 했다.**
- **일기 날짜를 하루 틀렸다.** 세션이 자정을 넘겼는데 `2026-08-11.md`를 새로 만들었다.
  병렬 세션이 이미 `2026-08-12.md`를 쓰고 있어서 발견했다 — **`date`를 안 찍고 파일 수정 시각으로 날짜를 짐작한 탓.**

**AI 협업 체크** *(코드 버그 말고 과정 레벨로)*:
- **사용자 질문이 사고를 막아준 것 — "안쪽 침범은 절대 있으면 안돼."**
  이 한마디가 없었으면 침범 0.16짜리 값을 그대로 두고 넘어갔을 것이다. 제약이 명시되자
  **Underlay라는 다른 축**을 찾게 됐고, 그게 최종 해법의 절반이 됐다.
- **사용자 질문이 사고를 막아준 것 2 — "왜 회색박스가 나와?"**
  설명하려다 내 앞선 설명이 틀렸다는 걸 발견했다. **설명을 요구받는 것이 검증 장치로 작동했다.**
- **추측으로 진행한 것 — 3번 캐릭터의 해금 조건.** 개발 세이브가 이미 정수 14761이라 웬만한 조건은 즉시 열려서
  "광활한 밭 승천1 + 정수 2000"을 **내가 정하고 선언**했다. 잠긴 모습을 보는 게 목적이었고 되돌리는 비용이 0인 자리였다.
- **자율적으로 잘 결정한 것** — 폰트 에셋을 고치기 전에 `Temp/fontbak/`에 백업했다.
  UI 전반이 쓰는 에셋이고 다른 세션의 미커밋 변경분이 섞여 있어 `git checkout`으로는 못 되돌리는 자리였다.
- **유저가 명시 안 한 전제 — "두껍다"의 기준.** 사용자는 네 번 모두 "얇다/굵다"만 말했고 나는 수치로만 답했다.
  중간에 **선택지를 나란히 렌더해 고르게** 한 뒤로는 한 번에 결정이 났다. 진작 그랬어야 했다.

**다음에 바꿀 것**:
- **[→ Kit] 한 값이 결과 둘을 동시에 움직이면, 고치기 전에 두 결과의 수식을 세운다.**
  트리거 자명 — *같은 파라미터를 고쳤는데 사용자가 **반대 방향 불만**을 말하는 순간*("얇다" 다음에 "침범한다").
  그건 손잡이가 부족한 게 아니라 **결과를 하나만 보고 있다는 신호**다. ✅ 템플릿·프로젝트 `CLAUDE.md` §1에 반영.
