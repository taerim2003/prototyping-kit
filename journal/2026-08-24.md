## 세션 1 — 블루베리 디펜스 (세션42, 일정 재수립 + 출시 준비)

**목표**: "오늘 계획은 일정을 다시 짜는 거랑 상점페이지 등록. 등록은 내가 할 테니 일정을 함께 논의해줘."

**한 일**: 칸반 7장을 전부 열어 잔여를 실측하고, 스팀 리뷰 규칙(상점·빌드 **각각 7영업일**, Coming Soon **2주 룰**)을
확인해 **9/25 출시에서 역산한 일정**을 짰다. 상점 Features 태그 선정, 게임패드 견적(→ Day1 패치 결정),
망치 진화 컨트롤러 2개 배선(세션38부터 남아 있던 것), `SfxLibrary` 생성 + 14슬롯 배선,
`companyName` 변경 + **레지스트리 세이브 이전**, 칸반 카드 3장 신설(스팀 출시 실무 · 빌드 설정 정리 · 게임패드).

**과정 — 잘 된 것**:
- 🔴 **상점 태그를 이름이 아니라 코드로 검증한 것.** "되감기" 스킬이 있으니 `Time Manipulation`이 맞아 보였는데,
  코드는 **"다른 스킬 쿨타임을 앞당김"**(`PlayerSkills.cs:17`)이라 시간 조작이 아니었다. `Controller`도 입력이 전부
  `Keyboard.current`뿐이라 뺐다. **둘 다 넣었으면 상점 페이지에 허위 표기가 박힐 자리**였고, 이름만 보고는 절대 안 갈렸다.
- 🔴 **전수 조사가 내 주장을 뒤집은 것.** `JuicyButton`의 `_originalScale = Vector3.one` 하드코딩을 찾고
  "오늘 재현될 것"처럼 말했는데, 두 씬의 JuicyButton **20개를 전수로 재니 전부 스케일 1.0**이라 지금은 재현이 안 되는
  잠재 버그였다. 표본 3개만 봤으면 같은 결론이 안 나왔다. 그 자리에서 정정했다.
- 🔴 **일정표에 안 적힌 의존을 찾은 것.** 사운드와 트레일러가 표에 나란히 있었지만 **사운드가 트레일러의 선행**이다.
  게다가 "빌드 리뷰 7영업일"이 진짜 마감이라 **9/12 빌드 제출**이 출시일보다 중요한 날짜라는 게 역산에서 드러났다.
- 🔴 **선택지가 두 개인 줄 알았던 자리에 세 번째가 있었다.** `companyName`을 바꾸면 세이브가 날아가는 문제에
  "마이그레이션 코드"와 "버리기"만 놓고 사용자가 버리기를 골랐는데, **레지스트리 키를 복사하면** 코드도 필요 없고
  버릴 필요도 없었다. 19개 값을 이름·내용 전수 대조까지 해서 옮겼다.
- **플레이스루를 헛돌지 않게 준비한 것.** "버그가 아닌 것" 10줄을 맨 앞에 둔 체크리스트를 만들었다 —
  소리 없음·망치 그림 안 바뀜·되감기 무연출은 전부 **아는 미완**인데, 안 알려주면 사용자가 버그로 적어 온다.

**과정 — 막힌 것 / 마찰**:
- 🔴 **체크박스 하나를 보고 "완료"라고 요약했다.** 「폴리싱 할일 리스트업」 카드의 `- [x] UI 에셋`을 근거로
  "UI 에셋 ✅완료"라고 적었는데, 그건 세션41의 **틀 교체**만 끝났다는 뜻이었고 **카드 본문의 UI 상세 리스트는 미체크가 훨씬 많았다**
  (메인화면·컬렉션·설정·스킬트리 엣지·대미지 표기·승리/패배 화면…). 그래서 UI 폴리싱을 일정 뒤로 뺐고,
  사용자가 *"아직 그래픽적인 것도 완벽하지 않은데. UI 이런거 개선 해야해"* 라고 해서야 드러났다. **일정을 다시 짰다.**
- 🔴 **`companyName`을 끝내 저장하지 못했다.** `AssetDatabase.SaveAssets()` · `File/Save Project` 메뉴 실행 ·
  `SaveToSerializedFileAndForget` **셋 다 무효**였다(마지막 것은 `true`를 반환하고 파일 mtime까지 갱신했는데 값은 그대로).
  게다가 그 내부 API는 **ProjectSettings를 통째로 덮어쓸 수 있는 수**였다 — `git status`가 깨끗해서 손상이 없었음을
  뒤늦게 확인했을 뿐, **던지기 전에 위험을 안 쟀다.** 결국 사용자에게 "Unity에서 저장해달라"로 넘겼다.
- 🔴 **도구가 알려준 타입을 믿고 3번 실패했다.** 레지스트리 복사에서 `GetValueKind`가 **DWord**라고 했지만
  실제 값은 **Int64**(`0x3FF0000000000000` = double 1.0)였다. Unity가 float PlayerPrefs를 QWORD로 저장한다.
  `$raw.GetType().Name`을 찍고 나서야 갈렸다 — **메타데이터가 아니라 값을 먼저 볼 일이었다.**
- **HANDOFF의 세이브 경로가 틀려서 잘못된 경고를 했다.** 문서에 적힌 `HKCU\Software\DefaultCompany\...`를 근거로
  "세이브가 날아간다"고 했는데, 정작 그 키엔 **Unity 내부 값 6개뿐**이고 게임 데이터가 없었다.
  진짜 개발 세이브는 `HKCU\Software\Unity\UnityEditor\...`였다. 값 이름을 열거하고서야 알았다.

**AI 협업 체크** *(코드 버그 말고 과정 레벨로)*:
- **사용자가 잡아준 것 2건.** ① 위 "UI 에셋 완료" 오독 — **일정 전체가 그 오독 위에 서 있었다.**
  ② `JuicyButton` 수정을 **취소**한 것. 나는 "고칠 수 있는 것"으로 분류했는데, **플레이스루 직전에 버튼 동작을 바꾸면
  결과 해석이 흐려진다**는 게 사용자 쪽 이유였다. 나는 "고칠 수 있나"만 봤고 **"지금 고쳐도 되나"는 안 봤다.**
- **선언하고 진행한 것이 먹혔다.** 망치 배선·`SfxLibrary` 생성은 손댈 곳을 한 줄로 선언하고 바로 갔고 안 끊겼다.
  반면 취소당한 `JuicyButton`은 **선언은 했지만 타이밍을 안 물은** 경우다 — 선언의 내용이 "무엇을"에만 있고 "지금"엔 없었다.
- **효과음을 "고르게" 하지 않고 "꽂아두고 바꾸게" 한 것.** 606개를 슬롯당 3~4개로 좁힌 뒤,
  후보 1순위를 **미리 다 배선**했다. 적 타격음처럼 **초당 여러 번 겹칠 때만 판단되는 소리**는 파일을 하나씩 들어선 못 고른다.
- **`/wrap`을 내가 호출하지 않은 것.** 세션40에 똑같이 "마무리해"를 받고 Skill 툴로 부르려다 막혔던 걸 기억해,
  이번엔 **먼저 "제가 호출할 수 없는 스킬"이라고 안내**했다. 규칙이 도구로 지켜지는 자리를 두 번은 안 밟았다.

**다음에 바꿀 것**:
- **[→ Kit] 체크박스·상태 표시를 근거로 "완료"를 말하기 전에 그 항목의 *하위 목록*을 볼 것.**
  트리거 자명 — *카드·문서의 `[x]`를 근거로 진행 상황을 요약하려는 순간.*
  체크박스는 **그 줄**만 말하지 아래 딸린 리스트는 말하지 않는다. 기존 규칙("HANDOFF의 ~해야 함을 코드로 확인")은
  **미완료 주장**만 의심해서 **완료 주장**엔 발동을 안 했다. 이번엔 그 반대쪽에서 틀렸고, **일정 전체가 그 위에 섰다.**
- **[→ Kit] 도구가 알려주는 타입·메타데이터를 근거로 쓰기 전에 실제 값을 한 번 찍을 것.**
  트리거 자명 — *`GetType`·`GetValueKind`·`typeName` 같은 걸 분기 조건으로 삼으려는 순간.*
  `GetValueKind`는 DWord라 했지만 실제는 Int64였고, 그걸 믿고 **3번 연속 실패**했다.
- **[→ Kit] 저장 API가 성공을 반환해도 파일을 되읽기 전엔 저장됐다고 하지 말 것.**
  트리거 자명 — *`Save*`류를 부른 직후.* `SaveToSerializedFileAndForget`은 `true`를 반환하고 **파일 mtime까지 갱신**했는데
  값은 안 바뀌어 있었다. "에셋을 코드로 만들면 되읽어 검증할 것"이 이미 스킬에 있는데 **ProjectSettings 같은 설정 저장엔 발동을 안 했다.**

**메모**: 세션 시작 시 `git status`에 `GDD.md`가 없었는데 종료 시엔 있었다 — 세션 중 사용자가 적 HP를 갱신했다
(콩콩이 22→34 · 서핑 9→20 · 보스 1200→500, §4-9 메타 진행 신설). 내 작업과 갈라내는 데 **세션 시작 스냅샷이 또 근거**가 됐다.

## 세션 2 — 블루베리 디펜스 (세션43, 컬렉션 화면)

**목표**: "컬렉션 패널 러프하게 만들어줘. 일단 알아서 레퍼런스 찾아서 만들어줘."

**한 일**: 타이틀의 컬렉션 도감 화면을 러프로 구현 — 발견한 스킬 격자 + 2루트×2티어 진화 트리.
발견 기록 저장(`CollectionSave`), 타이틀에서 아이콘을 집기 위한 `SkillIconLibrary`(굽는 도구 포함),
`UISkin`에 판 2종 추가. 곁가지로 **Multiple로 조각나 조각 하나만 보이던 아이콘 4장**을 고치고 참조 7곳 재배선.

**과정 — 잘 된 것**:
- **씬을 한 번도 안 건드리고 끝났다.** 만들기 전에 `Btn_컬렉션`이 이미 `TitleController.collectionButton`에
  꽂혀 있는 걸 확인해서, `OptionsMenu`식 런타임 생성으로 가면 **MCP 씬 편집이 0회**라는 게 처음부터 정해졌다.
  "넣을 곳이 아니라 이미 있는 곳부터 센다"가 실제로 작업량을 줄인 사례.
- **아이콘 배열을 손으로 꽂지 않고 굽는 도구로 만든 것.** 되읽기 검증을 넣었더니 그 김에
  **조각난 PNG 4장**이 드러났다 — 손으로 꽂았으면 "그림이 좀 이상한데" 하고 넘어갔을 자리다.
- 플레이모드 스크린샷 → 피드백 → 재작업 루프가 짧았다. 화면을 안 보여줬으면 "큰 판" 지적이 훨씬 늦게 나왔다.
- **사용자 PlayerPrefs를 되돌리기 전에 값을 먼저 읽은 것.** 내 테스트 시드인 줄 알았는데
  실제 플레이로 쌓인 기록이었다. 그냥 지웠으면 사용자 데이터를 날렸다.

**과정 — 막힌 것 / 마찰**:
- 🔴 **큰 판 하나로 다 만들었다가 통째로 다시 짰다.** 사용자가 중간에 끊고
  *"큰 패널 하나를 사용하지 마. 캐릭터 선택 화면처럼 … 작은 패널로 영역을 분할해서 써"* 라고 잡아줬다.
  그런데 그 규칙은 **바로 앞 세션에 생긴 카드 「폴리싱 남은거 훑기」에 이미 적혀 있었다** —
  *"큰 패널 안에 요소를 묶지 않고, 각 요소가 독립적으로 배치되어야 함"*, *"패널 원본 사이즈는 절대 변경 불가"*.
  **세션 첫 턴에 `brief`를 안 돌려서** 그 카드를 못 봤다. 사용자가 곧장 작업을 지시해서 그대로 코드로 들어갔다.
- 🔴 **없는 버그를 있다고 보고했다.** 씬 YAML에서 `guid:`가 붙은 줄을 세어 `passiveEvoIcons`를 12칸으로 읽었는데
  **실제로는 14칸**이었다 — 빈 칸은 `{fileID: 0}`이라 `guid`가 없어 내 집계에 안 잡혔다.
  "방어/가속 진화 아이콘이 어긋난다"고 보고했고, 고치는 코드를 짜서 **실행한 뒤에야** 아니라는 걸 알았다.
  (다행히 "길이가 12일 때만" 돌게 짜둔 가드 덕에 값은 안 망가졌다.)
  스킬의 "집계 숫자를 커버리지 근거로 쓰지 말 것"과 같은 갈래인데, 그 규칙은 **도구가 뱉은 숫자**만 말해서
  **내가 직접 센 숫자**엔 발동을 안 했다.
- 첫 결과 보고를 표와 파일 목록으로 던져서 *"설명좀 알아듣게 해봐"* 를 들었다. 러프 결과물 보고는 산문이 먼저다.

**AI 협업 체크** *(코드 버그 말고 과정 레벨로)*:
- **물어봤어야 하는데 추측한 것**: UI의 형태(큰 판 하나 vs 판 분할). 기능은 다 정해놓고 **배치를 추측**한,
  CLAUDE.md가 이름까지 붙여 경고하는 그 사고다. 다만 이번엔 "이 코드가 그리는 화면을 열거하라"로는 **안 걸렸을 것** —
  화면은 하나였고 틀린 건 그 화면의 **구성 원칙**이었다. 원칙은 코드에 없고 **칸반**에 있었다.
- **유저가 명시했어야 했나**: 아니다. 원본은 보드에 있었고 내가 안 봤다.
- **잘 결정한 것**: 씬 미편집 · 굽는 도구 + 되읽기 검증 · PlayerPrefs 되돌리기 전 확인 ·
  틀린 보고를 발견한 자리에서 바로 정정한 것.

**다음에 바꿀 것**:
- **[→ Kit] 씬·프리팹 YAML을 텍스트로 세어 배열 길이·개수를 판단하지 말 것.**
  트리거 자명 — *씬·프리팹 파일에서 `grep`으로 개수를 세려는 순간.*
  빈 칸은 `{fileID: 0}`이라 `guid`가 없어 안 세어진다. 개수는 에디터에 물어본다(`SerializedProperty.arraySize`).
  → `unity-mcp` 스킬에 반영함.
- **`brief`를 사용자 지시보다 먼저 돌린다.** 규칙은 이미 CLAUDE.md §7에 있다 — 새 규칙이 필요한 게 아니라
  **지시가 들어오면 곧장 코드로 가버리는 습관**이 문제다. 오늘은 그게 **판 하나 통째로 다시 짜기**로 돌아왔다.

**메모**: 설정 화면(`OptionsMenu`)은 아직 980×850 큰 판 하나다 — 「폴리싱 남은거 훑기」에
"설정 화면 전면 재설계: 패널 확대 금지"로 액션 아이템이 있다. 컬렉션에서 쓴 판 분할 방식을 그대로 쓰면 된다.
`Assets/Sound` **164MB**는 이번에도 커밋에서 뺐다.
