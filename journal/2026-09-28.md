**과정 — 잘 된 것**:
- **질문을 "코드 근거 + 기본값"으로 묶어 한 번에 던진 것.** 사용자가 8개·9개를 한 줄씩 번호로 답했고, 답이 곧 결정표가 됐다. 계획서에 그 표를 그대로 넣어 실행 중에 다시 물을 일이 없었다.
- **정답 원본을 먼저 대조해 둔 것.** 에이전트에게 "진화 이름의 정답은 TSV"라고 주기 전에 노션 「UI 문구 편집」과 TSV 56칸을 직접 맞춰 봤다. 그래서 "주석 이름이 낡았다" 판정을 의심 없이 적용할 수 있었다.
- **죽은 심볼은 에이전트 판정을 믿지 않고 한 번 더 셌다**(7개 전부 선언 1건만). 에이전트가 적은 라인 번호도 여러 개 어긋나 있어서, 편집 전에 grep으로 다시 찾은 게 맞았다.

**과정 — 막힌 것 / 마찰**:
- 🔴 **백그라운드 에이전트 하나가 사용자 인터럽트에 같이 죽었는데 "도는 중"이라고 두 번 말했다.** 사용자가 *"토큰 소모량이 없던데 그냥 멈춘 거 아니야?"* 라고 잡았다. SendMessage를 보내서야 "stopped by the user"를 알았다. 그 영역은 직접, 좁혀서 조사했다(메모리에 남김).
- 🔴 **질문을 코드 용어로 써서 세 번 못 알아들으셨다**(*"뭔소린지 모르겠는데"*). "기본 커브 폴백"·"flatten 마이그레이션"·"분출 VFX 순서"는 화면에서 벌어지는 일로 바꿔 썼어야 했다. 다시 쓰려고 코드를 보니 하나는 애초에 문제가 아니었다 — **화면 말로 바꿔 쓰는 과정이 곧 내 이해를 검산하는 과정**이다.
- 🔴 **병렬 세션과 부딪혔다.** 시작 때 `git status` 8줄이 작업 도중 100줄이 됐다(다른 세션의 진화 SO 밸런스). 두 가지가 터졌다:
  ① 그쪽이 지운 상수를 에디터 툴이 참조해 **컴파일이 막혔다** — 그쪽 결정대로 두 줄을 빼 풀었다.
  ② 번역 표 정리 스크립트의 `SaveAssets()`가 **그쪽이 메모리에서 들고 있던 한국어 표(70개)를 디스크로 밀어냈다**(545 → 70). mtime이 내 저장 시각과 초 단위로 같아 원인이 갈렸고, HEAD 복원 → 강제 재임포트 → TSV 재적재 → 내 키만 제거로 복구했다. **`/wrap` 0단계에서 표 개수를 세지 않았으면 모르고 지나갔다.**
- **커밋을 못 했다.** `PlayerSkills.cs` 한 파일에 내 주석 정리와 그쪽 진화 밸런스 변경이 섞였다. 파일 단위로 못 가른다.
