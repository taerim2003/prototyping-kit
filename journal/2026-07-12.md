## 세션 1 — 블루베리 디펜스

**목표**: 플레이 피드백 기반 밸런스 조정 + 빌드에서 스테이지가 전부 똑같이 나오는 버그 잡기.

**한 일**: 초반(1~10) 스폰 간격 단축, 관통·낙뢰 너프, 경험치 후반 감쇠(20스테=50%), 보물상자 11+ 2마리 등 밸런스 패스. 기본공격 진화의 비행 타격 미명중 문제는 발사점 상향+히트박스 세로 확대로 해결. 마지막에 "빌드에서만 스테이지가 동일"한 버그를 진단 — `StageTable.asset`의 `m_Script`가 null이고 에디터 전용 `m_EditorClassIdentifier`로만 타입이 잡혀 있어 빌드에서 SO가 null 로드되는 것이 원인. SO 클래스를 독립 파일로 분리하고 m_Script를 정상 참조로 교체. 밸런스·비행타격·빌드수정 모두 실플레이/재빌드 검증은 다음 세션 몫.

**과정 — 잘 된 것**: 빌드 버그 진단이 깔끔했음. "다른 SO 에셋들의 m_Script와 비교"라는 한 번의 grep으로 StageTable만 `{fileID: 0}`인 걸 즉시 특정 — 유저가 준 힌트(#UNITY_EDITOR, 빌드에서 파일 못 찾음)가 정확히 방향을 잡아줘서 헤매지 않았다. 증상(전 스테이지 동일)과 코드 폴백 경로(stageTable=null → 기본값)가 논리적으로 딱 맞아떨어져 확신을 갖고 고칠 수 있었다.

**과정 — 막힌 것 / 마찰**:
- 비행 타격 요청을 처음에 "화살을 기울여라"로 오해해서 회전 로직을 짰다가 유저가 "발사점을 올리란 뜻이었다"고 정정 → 전부 되돌리고 재작업. 한 번에 물어봤으면 왕복이 없었다.
- 세션 중간에 Unity MCP 연결이 끊겨서(38개 툴 소실) 빌드 수정을 파일 편집만으로 진행 → 재임포트/재빌드 검증을 내가 못 하고 유저에게 넘길 수밖에 없었다.

**AI 협업 체크**:
- **추측으로 진행한 것**: "살짝 위로 쏴줘"를 궤적 기울이기로 단정하고 바로 구현. 발사점 상향 vs 궤적 기울이기 두 해석이 갈리는 지점이었는데 물어봤어야 했다. (게다가 기울이기는 지상 사거리 손해라는 부작용까지 있어서 더 확인이 필요한 선택지였다.)
- **잘 한 자율 결정**: 빌드 버그를 SO 클래스 파일 분리로 해결하면서, "GameManager.cs에 합치는 게 CLAUDE.md의 기존 우회책이지만 그게 바로 이 버그의 원인"임을 인지하고 되돌아가지 않은 것. 우회책이 만든 부채를 정확히 짚었다.

**다음에 바꿀 것**:
- 시각/조작 관련 모호한 요청("살짝", "위로", "느낌")은 구현 전에 해석지를 한 줄로 확인하기. 특히 부작용(사거리 손해 등) 있는 선택지는 반드시. **[→ Kit]** 이미 CLAUDE.md §1에 있는 원칙인데 이번에 안 지킴 — 원칙 추가보다 "짧은 지시일수록 해석이 갈릴 수 있다"는 자각이 필요.
- **[→ Kit]** ScriptableObject 클래스를 다른 .cs에 곁다리로 넣으면 `m_Script`가 깨져 빌드에서만 null 로드될 수 있음 — "SO/MonoBehaviour 클래스는 파일명=클래스명으로 독립 파일에" 규칙을 CLAUDE.md §6 함정 목록에 추가 검토. (CLAUDE.md의 "새 .cs 미인식 시 기존 파일에 병합" 우회책과 정면 충돌하므로, 최소한 "SO는 예외" 단서를 달아야 함.)
