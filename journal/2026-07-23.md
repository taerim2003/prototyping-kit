# 2026-07-23

## 세션 1 — 블루베리 디펜스

**목표**: 플레이테스트에서 나온 버그·UX 지적 처리. (세션 중 계속 새 리포트가 들어와 사실상 "플레이 → 신고 → 수정" 루프)

**한 일**: UI 정리(타이틀 정수 표기·트리 죽은 자원 UI 삭제, 세이브 초기화 버튼 신설), 전투 버그 6종(미니 회오리 부양·비행 추격, 스나이핑 쿨마스크, 보물상자 보상 유실/순서, 모달 프리즈), **판을 넘어 남던 static 상태 전수 정리(`RunState`)**, 스킬트리 에디터 배치 파손 복구 + 원인 수정, 스킬트리 안개(fog of war), 승천 정수 배율. 실플레이 검증은 전부 사용자 몫이라 각 항목마다 "확인 포인트"를 같이 넘김.

**과정 — 잘 된 것**:
- 사용자가 **스크린샷 + 콘솔 로그를 같이** 던져준 덕에 프리즈 원인(닫힘 트윈의 `OnComplete`가 재오픈된 패널을 꺼버림)을 추측 없이 특정했다. 로그의 TMP 워닝은 무관했지만, 그걸 판별하는 것도 로그가 있어서 가능했다.
- MCP `script-execute`로 **에디트 모드에서 검증**한 게 두 번 결정적이었다. static 리셋은 일부러 오염시킨 뒤 `RunState.ResetAll()` 돌려 값이 돌아오는 걸 확인했고, 스킬트리 복구도 메모리/디스크 노드 수를 직접 찍어 비교했다. "플레이해봐야 안다"의 범위를 꽤 줄일 수 있다.
- 신고된 증상(패시브 하나)만 고치지 않고 mutable static을 전수 조사한 것. 낙뢰·보물상자 확률·`ModalPause`까지 같은 부류가 더 있었다.

**과정 — 막힌 것 / 마찰**:
- **내 수정이 다음 버그를 낳는 연쇄가 두 번.** 보물상자 보상 유실을 대기열로 고쳤더니 "보물에서 스킬 뽑으면 보너스가 안 터진다"가 생겼고(모달 순서가 뒤바뀜), 스킬트리 에디터를 리라이트했더니 연결 끊기 버튼이 클리핑돼 사라졌다. 둘 다 사용자가 발견. **바꾼 코드의 인접 동작을 스스로 한 번 훑는 절차가 없다.**
- 스킬트리 에디터가 **사용자가 정돈한 배치를 조용히 파손**하고 있었다(뷰 밖 window를 Unity가 끌어당긴 좌표를 그대로 에셋에 되씀). 다행히 커밋과의 차이가 좌표 33줄뿐이라 무손실 복구했지만, 하루치 작업이 날아갈 수 있었다.
- 세션이 길어지며 컨텍스트가 "직전 수정"에 쏠려, 초반 작업(정수 표기 삭제 등)의 검증 상태를 스스로 추적하지 못했다.

**AI 협업 체크**:
- **추측으로 진행한 것**: 스킬트리 안개 사양. "내가 연 노드 근처만 `?`"를 그대로 구현하면 **구매 전에 노드 이름을 볼 수 없다** — 게임 감각이 크게 달라지는 결정인데 확인 없이 진행하고 사후에만 언급했다. 한 줄 물었어야 했다.
- **암묵적으로 넘어간 전제**: "세이브 초기화"의 범위. `PlayerPrefs.DeleteAll()`이면 해상도 설정까지 날아가는데, 판단 근거(예전 빌드의 이름 모를 키까지 지워야 함)만 대고 실행했다. 결과적으로 옛 키(`meta.powder`·`meta.crystal`)가 실제로 남아 있어 맞는 선택이었지만, 그건 **나중에 레지스트리를 열어보고 안 것**이다.
- **잘한 결정**: static 누수를 전수 조사해 `RunState` 한 곳으로 모으고, "새 static 추가하면 여기 등록" 주석을 박아둔 것. 증상 하나만 고쳤으면 나머지가 그대로 남았다.

**다음에 바꿀 것**:
- **[→ Kit]** 버그 수정 후 **"이 수정이 바꾼 흐름의 앞뒤 한 단계"를 스스로 점검**하고 결과를 보고에 적기. 이번 두 연쇄는 모두 "모달이 열리는 순서", "노드가 그려지는 폭"처럼 바로 옆 단계였다.
- **[→ Kit]** 에디터 툴이 **사용자 편집 데이터에 write-back하는 코드**는 별도 위험군으로 보기. UI 프레임워크가 좌표를 보정할 수 있는 곳에서 그 값을 그대로 저장하면 데이터가 조용히 썩는다.
- 게임플레이 **감각을 바꾸는 사양**(무엇을 숨길지, 무엇을 지울지)은 구현 전에 한 줄 확인. 코드 구조 결정은 그냥 진행해도 됐다.

**메모**: Windows 빌드의 `PlayerPrefs`는 파일이 아니라 레지스트리(`HKCU\Software\DefaultCompany\BlueberryDefense`). 친구가 `AppData/LocalLow`를 지워도 세이브가 그대로여서 한참 헤맸다. 다음 프로토타입에서도 배포 전에 "세이브 초기화" 수단을 게임 안에 넣어두는 게 낫다.
