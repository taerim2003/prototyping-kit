**한 일**: 일정을 원본(노션 캘린더·칸반)으로 재진단하고 이번 주 범위를 확정했다(소리·번역·스킬 이펙트).

**과정 — 잘 된 것**:

  HANDOFF 미러와 일치함을 확인한 뒤에 말했다. 게다가 **진짜 문제가 날짜가 아니라 "아트 손이 하나인데 세 군데서 필요한 것"**이라는
  진단이 거기서 나왔다 — 표만 보고 "며칠 밀까요"를 물었으면 못 찾았을 자리다.
- 🔴 **착수 순서를 코드→규격에서 규격→코드로 뒤집은 것.** 이번 주는 사용자·친구 **둘이 동시에 그림을 그리는 주**였다.
  코드부터 짰으면 규격 없이 그린 그림을 받아 다시 그려야 했다. "리드타임이 긴 것부터"가 이번엔 코드가 아니라 문서였다.
- 🔴 **어셈블리 경계를 미리 의심한 것.** `JuicyButton`이 `Assets/Scripts` 밖(`Assets/JuicyUI/Runtime/`)에 있는 걸 보고
  배선 직후 asmdef를 찾아봤다. 실제로 있었고, 그대로 뒀으면 컴파일이 깨졌다.
  **당시 Unity가 꺼져 있어 검증이 불가능했으므로, 안 의심했으면 다음 세션까지 몰랐을 것이다.**
- **커밋 직전에 컴파일을 확인한 것.** 사용자가 "그냥 커밋해"라고 했지만 마침 Unity가 켜져서 30초로 검증했다.
  리플렉션으로 **두 어셈블리가 실제로 분리돼 있다는 것까지 값으로** 찍었다(`JuicyUI.Runtime` vs `Assembly-CSharp`).
- 🔴 **164MB를 그냥 커밋하지 않은 것.** "그냥 커밋해"를 문자 그대로 따랐으면 음원 팩이 git 히스토리에 영구히 박혔다.
  608개 중 쓸 건 14개다. 용량을 재고 대안 3개를 제시한 뒤 결정을 넘겼다.
- **Unity가 꺼진 상태에서 에디터 도구로 전환한 것**(세션35 패턴 재사용). `SfxLibrarySetup` 메뉴를 만들어 두고 넘겼다.

**과정 — 막힌 것 / 마찰**:

  "미검증"을 달고 인계할 뻔했다. 사용자가 후반에 에디터를 켜서 해소됐다 — 운이었다.

**AI 협업 체크** *(코드 버그 말고 과정 레벨로)*:
- **사용자 질문이 사고를 막아준 것 — "실제로 사용하려면 좀 잘라야 할까?"**
  이 한마디가 Panel 검토의 트리거였고, 열어 보니 **한 장인 줄 알았던 게 16조각 시트**였다.
  안 물었으면 다음 세션에 그대로 배선하다 걸렸을 것이다. 세션35의 `Effect_Arrow*`(자동 슬라이스로 조각남)와 **정확히 같은 함정의 반대 방향** —
  그때는 "쪼개지면 안 되는데 쪼개져 있었고", 이번엔 "쪼개야 하는데 통짜로 들어왔다".
- **추측으로 진행한 것 — 진화 이펙트 파일명 규칙**(`Effect_{스킬}_P{루트}T{티어}`).
  기존 `Effect_ArrowR1`이 이미 "화살 R0루트의 1차"로 이름을 다 써버려서 다른 루트를 표현할 수 없다는 걸 발견하고,
  새 규칙을 **"이대로 갑니다, 아니면 지금 끊어주세요"로 선언**하고 넘어갔다. 아직 적용은 안 했다 —
  **그림이 한 장도 안 나온 시점이라 되돌리는 비용이 0인 자리**였다. 이 절충은 재현할 만하다.
- **자율적으로 잘 결정한 것** — 커밋을 성격별로 2개로 나누고(코드 / 아트), **다른 세션 파일은 손대지 않은 것.**
  `git status`의 모든 줄을 설명할 수 있는지 확인했고, 설명 못 하는 줄(폰트 세션의 TMP 에셋)은 남겼다.
- **유저가 명시 안 한 전제 — UI 스타일 방향.** 어제 준 사양서는 픽셀아트 기준(1도트=3px, 안티에일리어싱 금지)인데
  오늘 들어온 Panel은 **매끈한 벡터풍**이다. 어느 쪽이 의도인지 확인하지 못한 채 세션이 끝났고,
  **친구에게 준 사양서가 여기에 달려 있다**(방향이 바뀌면 사양서도 고쳐야 한다). HANDOFF에 미결로 남겼다.

**다음에 바꿀 것**:
- **[→ Kit] 커밋 전에 새로 들어온 폴더의 용량을 잰다.** git 히스토리는 되돌리기가 가장 비싼 축이고,
  에셋 팩·음원·동영상은 "그냥 커밋해"에 섞여 들어오기 쉽다. 트리거 자명 — *`git status`에 새 디렉터리(`?? xxx/`)가 보이는 순간 `du -sh`.*
  100MB를 넘으면 커밋 전에 알리고 대안(고른 것만 / LFS / 제외)을 제시한다.
- **[→ Kit] `Assets/Scripts` 밖의 코드를 편집하기 전에 asmdef를 찾는다.** Unity에서 asmdef가 있는 어셈블리는
  기본 어셈블리(`Assembly-CSharp`)를 **참조할 수 없다** — 참조 방향이 단방향이라 그쪽에서 이쪽 클래스를 부르면 컴파일이 깨진다.
  해법은 이벤트로 방향을 뒤집는 것. 트리거 자명 — *`Assets/Scripts` 밖 파일에 다른 폴더의 클래스를 호출하는 줄을 추가하려는 순간
  `find Assets -name "*.asmdef"`.* 서드파티 UI·플러그인 폴더가 특히 그렇다.
