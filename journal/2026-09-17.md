## 세션 1 — 블루베리 디펜스 (세션 67: 빌드 QA — 세이브 초기화 · 포도 해금)

**목표**: 빌드에서 "세이브 초기화가 안 된다" 수정 + 포도 해금이 정상인지 확인.

**한 일**: 원인은 코드가 아니라 **빌드가 리셋 코드 수정보다 22초 먼저 뽑힌 것**이었다(빌드 22:19:16 < `OptionsMenu.cs` 22:19:38).
빌드 레지스트리는 비어 있고 `save.json`은 마이그레이션 직후 그대로, `.tmp` 흔적 없음 — 셋이 같은 설명을 가리켰다.
재빌드로도 남는 구멍(타이틀 화면들이 한 번만 지어져 리셋 후 **잠긴 캐릭터로 판이 시작됨**)은 리셋 뒤 타이틀 재로드로 막았다.
포도 해금은 에디터에서 정수×클리어 6조합을 실측해 정상 확인. 칸반 「실제 exe QA」를 진행 중으로 옮기고 재빌드 확인 항목을 붙였다.

**과정 — 잘 된 것**:
- **추측 전에 디스크의 흔적을 셌다** — 세이브 폴더 파일·mtime, 빌드 레지스트리, Player.log, Editor.log의 빌드 시각. 가설 하나(`File.Replace`가 Mono에서 실패)는 스크래치패드에서 실제 Unity Mono로 돌려 5분 만에 기각했다.
- "`.tmp`가 **없다**"는 부재 증거가 가설을 뒤집었다 — 저장 실패가 아니라 저장이 **안 불린 것**.
- 에디터 실측은 `save_editor.json` 백업 → `Save()` 안 부르고 메모리만 바꿔 측정 → 원복 → 바이트 비교로 끝냈다.

**과정 — 막힌 것 / 마찰**:
- 오프라인 컴파일 체크에서 `sed`가 rsp 치환 경로의 백슬래시를 먹어 한 번 실패. 슬래시(`C:/...`) 경로로 바꾸니 통과.
- 오늘 앞선 세이브 이관 세션이 `/wrap` 없이 끝나 미커밋 변경 11개가 이번 세션과 섞였다.

**AI 협업 체크**:
- 추측으로 진행한 것: 리셋 후 "완료 문구를 보여주는 대신 타이틀 재로드"(HANDOFF 확인 대기에 기록).
- 노션 카드 본문을 유니코드 이스케이프로 보냈다(규칙 위반). 되읽기로 글자가 온전한 건 확인했지만 운이었다.
- 잘한 것: 빌드에서만 나는 문제를 코드부터 파지 않고 **빌드 시각 대 소스 수정 시각**으로 갈랐다.

**다음에 바꿀 것**:

- 오프라인 컴파일 메모리에 "경로는 슬래시로" 추가.

**메모**: 빌드 폴더(`Build/`)가 22:22 이후 비어 있었다 — 사용자가 다시 뽑는 중으로 보고 건드리지 않았다.

## 세션 2 — 블루베리 디펜스 (Steam 빌드 리뷰 반려: Steam Cloud)

> 시간상으로는 세션 1보다 **먼저** 시작했다. `/wrap` 없이 멈춰 있던 사이 세션 1이 이 작업까지 같이 커밋했다(2408d92).

**목표**: Steam 빌드 리뷰 반려("Steam Cloud 표시가 있는데 동기화가 안 되고, Steamworks에 경로가 없다") 해결 + 사용자가 할 일 정리.

**한 일**: 원인은 세이브가 전부 `PlayerPrefs`(=레지스트리)였던 것 — Auto-Cloud는 파일만 올린다. SDK가 없어서 Auto-Cloud로 가기로 하고
`SaveStore`(PlayerPrefs 모양 API, `LocalLow/.../save.json`, 임시 파일 교체 저장, 옛 레지스트리 1회 마이그레이션)를 만들어 호출부 7곳을 치환.
빌드·에디터 두 설정으로 오프라인 컴파일, 사용자가 뽑은 빌드의 `save.json`을 레지스트리와 값 단위로 대조. 칸반에 반려 대응 카드 생성.

**과정 — 잘 된 것**:
- 세이브 폴더를 열어 보니 `Player.log`가 같은 곳에 있었다 → Steam 패턴을 `*`가 아니라 `save.json`으로 좁힌 근거가 추측이 아니라 실측이 됐다.
- 에디터가 플레이 중인 걸 첫 호출에서 확인하고, 세이브를 건드리는 테스트를 접고 읽기 전용 대조만 했다.
- 스킬트리 문자열이 레지스트리와 "다르다"가 나왔을 때 틀렸다고 보고하지 않고 노드 집합으로 쪼개 봤다 — 레지스트리가 파일의 부분집합(이후 해금분)이었다.

**과정 — 막힌 것 / 마찰**:
- **내가 편집하는 동안 사용자가 빌드를 뽑았다** — 빌드(22:19:07)가 `OptionsMenu.cs` 수정(22:19:38)보다 빨라 리셋이 빠진 빌드가 나갔고, 세션 1이 그걸 버그로 받아 추적했다.
- `/wrap` 전에 턴이 끊겨 미커밋 변경이 다른 세션과 섞였다.

**AI 협업 체크**:
- 추측으로 진행한 것: 음량·언어도 클라우드 동기화 · 에디터 세이브 파일 분리 · 레지스트리 마이그레이션 (HANDOFF 확인 대기 [9/17]).
- 규칙 위반: 칸반 카드 생성에 한글을 유니코드 이스케이프로 보냈다. 되읽어 온전함은 확인.

**다음에 바꿀 것**:

## 세션 3 — 블루베리 디펜스 (스킬트리 3건: 해금 시기 · 리롤 순서 · 스탯 등속)

**목표**: 스킬 해금이 한 시기에 몰림 · 리롤 횟수 노드가 리롤 해금보다 먼저 보임 · 스탯 노드가 후반일수록 커짐 — 셋 다 고치기.

**한 일**: 트리 모양·좌표는 그대로 두고 **칸에 앉은 노드만 맞바꾸는** 방식으로 해금 3종을 가지 안쪽으로 내리고 대역을 올렸다(산탄 2·호밍 2·되감기 3).
리롤 해금은 루트 옆으로 올려 리롤 노드 넷을 전부 그 가지 안에 넣었다. 스탯은 노드당 같은 값(만렙 총합 유지).
에셋 YAML 되쓰기 → 되읽기 불일치 0 → 에디터 재임포트 확인 → TSV·번역 표 적재(언어별 15건). 병렬 세션이 밸런스 작업 중이라 플레이모드는 안 켰다.

**과정 — 잘 된 것**:
- 이전 세션 시뮬레이터가 안 남아 있어 **모의 플레이어를 새로 짜서 "지금 값"부터 쟀다** — 해금 5종이 1~3판에 몰린 게 수치로 나와 요청이 현상임을 먼저 확정했다.
- "먼저 **보는**"을 읽고 UI의 안개 규칙을 열어 본 덕에 가격이 아니라 **선행**이 답이라는 게 코드로 갈렸다. 가격으로 밀었으면 검사는 통과하고 화면에선 그대로였을 것.
- 제약 검사(강화는 해금 아래 · 리롤은 리롤 해금 아래 · 은/금별 등급 보존)를 **고치기 전 트리에 먼저 돌려 4건이 걸리는 걸 보고** 나서 설계안에 썼다.
- 대역 조합을 셋 비교해 "호밍 3이면 호밍·되감기가 또 같은 판에 붙는다"를 잡았다 — 요청의 핵심이 "비슷한 시기"라 늦은 셋끼리도 벌려야 했다.

**과정 — 막힌 것 / 마찰**:
- `assets-refresh`가 **다른 세션의 편집 중 컴파일 에러**를 돌려줬다. 파일 수정 시각(4초 전)으로 내 것이 아님을 갈랐다.
- 가격을 올리면 **이미 산 노드의 지불액이 재계산돼** 개발 세이브 정수가 −248이 됐다. 설계 단계에선 못 봤고 에디터 되읽기에서 걸렸다.

**AI 협업 체크**:
- 추측으로 진행한 것: 대역 조합 · 리롤을 선행으로 막음(원칙 "가격으로 유도"의 예외) · "등속"=노드당 같은 값 · 체력 반올림 8 (HANDOFF 확인 대기 [9/17] 스킬트리).
- 규칙 위반: 칸반 카드 수정에 한글을 또 유니코드 이스케이프로 보냈다(오늘 두 번째). 되읽기 단계에서 온전함 확인 — 규범은 안 먹히고 되읽기 단계가 방어선 역할을 하고 있다.
