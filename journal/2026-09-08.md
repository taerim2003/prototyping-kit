## 세션 1 — 블루베리 디펜스 (세션 59)

**목표**: 칸반 「버그 수정」을 `/loop 10m`로 끝까지 밀고, 이어서 GDD를 기획 문서로 전면 재작성.

**한 일**: 「버그 수정」 14항목 전부 닫음(카드 완료). 데미지 숫자 큐 제거 · 진화 노드 피봇 ·
암살 사격 재설계 4건 · 진화 쿨감 폐지 · 보물상자 진화 게이트 2건 · 스킬트리 노드 1.5배 · 아웃라인 색 ·

그리고 **GDD 전면 재작성**과 노션 「스킬 데이터 시트」 재생성.

**과정 — 잘 된 것**:

- **대조군을 먼저 돌리는 습관이 세 번 살렸다.** SO 손잡이 검증에서 "값을 넣어도 안 변한다"가 나와
  죽은 층인 줄 알았는데, 대조군(값 0)도 같은 값이라 **검사 환경**을 의심하게 됐다.
  원인은 코드가 아니라 `Prog()` 조회맵이 `Awake`에서만 만들어져 **에디트모드엔 null**인 것이었다.
  배틀 씬에서 다시 재니 대조군·양성 대조가 깔끔히 갈렸다.
- **`/loop`가 이번에도 잘 맞았다.** 10분마다 같은 프롬프트가 들어오니 "다음에 뭘 할까"를 매번 스스로 정했고,
  종료 조건(시각 상한 + 카드 미체크 0)을 프롬프트에 박아 둔 덕에 **사고로 끊긴 게 아니라 조건으로 멈췄다.**
- **"거래의 한쪽만 지우지 않는다"를 스스로 잡았다.** 진화 쿨감을 걷어내다 독수리 「급강하 폭격」의
  **투하 −1 페널티**가 쿨감의 짝이었다는 걸 주석에서 보고, 대가만 남아 순손해가 된 걸 같이 걷어냈다.

**과정 — 막힌 것 / 마찰**:

- 🔴 **폐지된 기능을 "구현돼 있다"고 단정하고, 맞는 문서를 고쳤다.**
  `Enum.GetValues(PassiveSkillId)`로 패시브를 세어 7종이라 보고, 태리미의 노션 기획서(6종)가 틀렸다며 리프레쉬를 **추가**했다.
  실제로는 2026-08-06에 폐지됐고 enum·에셋은 정수 직렬화 때문에 남겨 둔 껍데기였다.
  `LevelUpUI`의 후보 배열에 **주석으로 "Refresh는 폐지돼 빠졌다"** 라고 적혀 있었는데 그걸 안 봤다.
  태리미가 *"리프레쉬 패시브 이제 없잖아"* 라고 해서야 드러났다.
- 🔴 **유니코드 이스케이프로 한글을 보내 두 글자가 깨졌다.** `뒤덮다`→`뒤덦다`, `뜹니다`→`뜽니다`.
  kanban 스킬에 **"한글 그대로 쓸 것"이 🔴로 박혀 있는데** 그대로 밟았다.
  반환 마크다운 대조 단계가 있어서 잡혔다 — 그게 없었으면 사용자 문서에 오타가 남았다.
- **미완성 목록을 문서에서 베껴 과장했다.** "2차 진화 그림이 전무하다"를 HANDOFF에서 그대로 옮겼는데,
  세어 보니 **아이콘 R2는 16종 다 있었다.** 없는 건 이펙트 2종을 뺀 나머지였다.
  "스킬트리 배치 미완"도 실제로는 34노드가 들어가 있었다.
- **오프라인 컴파일이 새 `.cs`에서 한 번 실패했다.** rsp의 소스 목록이 마지막 컴파일 시점 것이라
  새 파일이 빠져 있었고, 원본 rsp 마지막 줄에 개행이 없어 append가 붙어버리는 것까지 겹쳤다.

**AI 협업 체크** *(코드 버그 말고 과정 레벨로)*:

- **추측으로 간 것**: 위 리프레쉬 건이 그것. 게다가 **추측으로 사용자 문서를 고쳤다** — 읽기만 했으면
  되돌릴 게 없었을 텐데 쓰기까지 갔다.
- **잘 결정한 것**: 진화 SO 44개를 **빈 채로** 만든 것. 값을 채우면 44개 진화의 밸런스를 내가 지어내는 셈이라
  손잡이만 만들고 비워 뒀다. 「가속 되감기」 2차도 태리미가 정할 자리로 남겼다.
- **정정을 세 번 했다**: "네 티어가 비었다"(실제로는 하나), "패시브 7종"(6종), "2차 진화 그림 전무"(아이콘은 다 있음).
  셋 다 **에셋·enum 껍데기를 보고 게임 상태를 추론**한 같은 실수였다.

**다음에 바꿀 것**:

- **[→ Kit] enum·에셋에 값이 있다고 그 기능이 게임에 있는 게 아니다 — *진입점 배열*을 봐야 한다.**
  기존 규칙("코드에 스위치가 있다 ≠ 게임에 그 기능이 있다")은 **에셋이 켜는 것**만 말해서,
  **폐지됐지만 직렬화 때문에 남은 enum 값**엔 발동을 안 했다. 직렬화 enum은 지우면 뒤 값이 밀려서 **일부러 남긴다.**
  트리거 자명 — *`Enum.GetValues`나 에셋 개수로 "N종"을 세려는 순간.*
  → **그 목록을 실제로 소비하는 배열**(레벨업 후보·스폰 테이블 등)을 찾아 거기서 센다.
- **[→ Kit] 사용자 문서와 구현이 어긋나 보이면, 문서를 고치기 전에 "내가 틀렸을 경우"를 먼저 친다.**
  문서는 사람이 결정을 담아 쓴 것이고 코드 껍데기는 관성으로 남는다 — **어긋남의 기본값은 내 오독**이다.
  트리거 자명 — *사용자가 쓴 문서를 내 조사 결과로 고치려는 순간.* 근거를 하나 더 대고 나서 고친다.

## 세션 2 — 블루베리 디펜스 (세션 60)

**목표**: 코드 전체를 돌며 레거시를 걷어내고 주석을 현재에 맞게 경량화. 리팩토링 규모는 아님.

**한 일**: 92개 파일 15,477줄을 전수 조사해 **순감 737줄**(44개 파일 · +164/−901). 참조 0건인 죽은 코드
(LevelUpUI 조합 미리보기 클러스터 120줄 · UISkin 런타임 API 12개 · UISkinApply의 실행된 적 없는 설정 102줄 등)를
지우고, 중복 넷을 합쳤으며(`UITreeUtil.FindDeep`·`ObjectPool.SpawnTimed`), 사실이 아닌 주석 30여 건을 고쳤다.
검증은 오프라인 컴파일(런타임·에디터 두 어셈블리 에러 0) + 플레이모드 9화면 캡처.

**과정 — 잘 된 것**:

- **"주석을 경량화해줘"를 곧이곧대로 하지 않은 것.** CLAUDE.md가 주석을 *결정 보관소*로 지정해 놨으므로,
  무차별 축소는 규칙 위반이 된다. 기준을 먼저 세우고(정정 / 코드 재진술만 삭제 / "왜"는 불가침) 플랜에 못 박았더니
  이후 판단이 한 번도 흔들리지 않았다.
- **씬 계층을 awk로 전부 떠서 대조한 것.** `UISkinApply`의 경로가 죽었는지 살았는지를 grep으로는 못 가린다
  (`m_Father`를 따라 올라가야 전체 경로가 나온다). 한 번 짜 두니 캐릭터 선택·맵 선택·진화창을 연달아 재서,
  **"한 번도 실행된 적 없는 설정 102줄"**이라는 결론을 추측 없이 낼 수 있었다.
- **오프라인 컴파일이 두 번 다 값을 했다.** `IsSpawningPaused`를 `IsStageBreak`과 같이 지운 실수를 즉시 잡았고,
  에디터 어셈블리를 **내가 방금 만든 `AC.ref.dll`을 참조하도록** 바꿔 컴파일해서 에디터 툴의 끊긴 참조까지 확인했다.

**과정 — 막힌 것 / 마찰**:

- 🔴 **조사 에이전트 셋이 입을 모아 "Refresh 패시브 분기는 죽었다"고 했는데 틀렸다.** 셋 다
  `LevelUpUI`의 레벨업 후보 배열만 보고 "획득 경로가 없다"고 결론냈다. 실제로는 `CheatWindow`가
  `Enum.GetValues`로 **enum 전체**를 순회해 획득 버튼을 만들어서 에디터에서는 도달한다.
  지우기 직전에 치트 창을 열어 본 덕에 멈췄다 — **안 봤으면 테스트 경로를 조용히 부쉈다.**
- `sed`로 라인 범위를 지우다 **`SkillTreeData.effect` 필드를 통째로 날렸다.** 주석 한 줄을 옮기려고
  `-e '33d' -e '33i'`를 연달아 쓴 게 원인. 컴파일 전에 diff를 봐서 잡았지만, 애초에 Edit 툴로 했어야 했다.
- 「일괄 삭제」를 라인 번호로 하다 보니 **이음새(빈 줄·중괄호)를 매번 따로 확인**해야 했다. Whirlwind에서는
  `else` 블록을 지우고 남은 중괄호와 들여쓰기를 두 번에 걸쳐 고쳤다.

**AI 협업 체크** *(코드 버그 말고 과정 레벨로)*:

- **물어봤어야 하는데 추측으로 진행한 것**: 없다고 본다. 갈림길 셋(UISkinApply를 지울지 고칠지 ·
  되살릴 배선이 딸린 죽은 함수 · 픽업 공통화)은 전부 골라서 끝내고 HANDOFF 「확인 대기」에 적었다.
- **암묵적으로 넘어간 전제**: "경량화"의 뜻. 사용자는 "중요한 것만 남기고"라고 했는데 이 프로젝트에서
  *중요한 주석*은 오히려 남겨야 할 쪽이었다. 기준을 플랜에 적고 승인을 받아 어긋남을 막았다.
- **자율적으로 잘 결정한 것**: 에이전트가 "가장 심각"이라고 올린 **진화 봉인 미작동**을 버그로 처리하지 않은 것.
  HANDOFF 세션59에 *"노드 배치는 태리미 몫"*이라고 **이미 적혀 있었다.** 인용 전에 원본을 연 게 맞았다.

**다음에 바꿀 것**:

- **[→ Kit] "이 코드는 아무도 안 부른다"를 말하기 전에 *에디터 전용 호출부*를 따로 센다.**
  기존 규칙들은 씬·프리팹 GUID와 런타임 참조는 재라고 하는데, **`Assets/Editor/`의 치트·베이크 도구**는
  빠뜨리기 쉽다. 특히 그 도구들이 `Enum.GetValues`로 **전체를 순회**하면, 게임에서 폐지된 값도 여전히 도달한다.
  트리거 자명 — *참조 0건을 근거로 코드를 지우려는 순간.* → `Assets/Editor`를 grep 범위에 넣고,
  enum 값이면 **그 enum을 통째로 순회하는 곳**이 있는지 한 번 더 본다.
- **[→ Kit] 여러 줄을 지우고 그 자리에 넣을 때는 `sed`가 아니라 Edit 툴을 쓴다.**
  `sed -e 'Nd' -e 'Ni\...'`는 **첫 번째 편집이 라인 번호를 밀어서** 엉뚱한 줄을 지운다.
  트리거 자명 — *한 `sed` 호출에 `d`와 `i`/`c`를 같이 쓰려는 순간.* 순수 삭제(범위 하나)만 `sed`로 하고,
  치환·삽입은 Edit 툴로 한다.

**메모**: 정리 중 나온 **실동작 이상 6건**(도감에 포도 안 뜸 · 확장 스테이지 비행선 누락 · 호버음 무음 등)은
손대지 않고 칸반 카드 「코드 정리 중 발견한 버그 6건」으로 올렸다. 전부 코드 정리가 아니라 기능 수정이라 범위 밖이다.
