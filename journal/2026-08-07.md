## 세션 1 — 블루베리 디펜스 (세션35)

**목표**: "힘 – 산탄 장착 : Q키에 할당된 스킬 강화"가 구현돼 있는지 확인 + 사용자가 그린 진화 아이콘 전부 배선.

**한 일**: 힘 R1이 명세와 다르게 "화살 쏘기 고정 강화"로 돼 있던 걸 확인해 보고하고, Q 슬롯 기준으로 교체.
진화 아이콘 32종을 `LevelUpUI` 단독 소유 배열에 배선하고 6개 화면(HUD·레벨업/보물/진화 카드·조합 미리보기·진화 트리·ESC)에 태웠다.
화살 진화 투사체 2종(1차/2차)도 붙였다. 재배선용 에디터 도구를 만들어 남겼다.

**과정 — 잘 된 것**:
- **Unity가 꺼져 있어 MCP가 없는 상태에서 "에디터 도구를 만들어 두고 나중에 한 번 돌린다"로 전환한 것.**
  사용자에게 "Unity 켜고 재시작해 주세요"로 세션을 끊지 않고 코드를 끝까지 밀 수 있었고, 뒤에 MCP가 붙었을 때 그 도구를 그대로 재사용했다.
  **덤으로 아이콘을 다시 그릴 때 쓸 도구가 남았다** — 일회성 배선 스크립트였으면 다음에 또 짰을 것.
- **"임포트 정규화 0장"을 그냥 넘기지 않은 것.** 할 일이 없었던 건지 검사가 무력했던 건지 구분이 안 돼서
  일부러 1장을 망가뜨려 재실행했고, 정확히 1장을 잡아 되돌리는 걸 보고서야 "0장"을 믿었다.
- 아이콘 `R1/R2`가 루트인지 티어인지를 **그림을 직접 열어** 4쌍(화살·회오리·산탄·건강)으로 교차검증한 것.

**과정 — 막힌 것 / 마찰**:
- **`Effect_Arrow*`가 Multiple 자동 슬라이스로 2조각 나 있었다.** 배선 직전 프로브에서 스프라이트 이름이 `_1`로 찍혀 걸렸다
  — 아이콘 32장은 조각이 하나뿐이라 안 걸렸는데 이펙트만 걸린 것. 못 봤으면 **화살 그림의 잔상 조각만 날아갈 뻔했다.**
- `script-execute`에 보낸 코드가 `using System.Linq`·`using UnityEngine.SceneManagement` 누락으로 2번 컴파일 실패.
  한 줄짜리 긴 코드라 매번 전문을 다시 보내야 해서 왕복이 비쌌다.

**AI 협업 체크** *(코드 버그 말고 과정 레벨로)*:
- **물어봤어야 하는데 추측으로 진행한 것 — `R1/R2`의 의미.** 그림으로 검증은 했지만 사용자에게 확인은 안 받았다.
  그리고 실제로 **`Effect_Arrow*`는 티어였다**(사용자가 나중에 "R2는 2차 진화"라고 정함) — **같은 접미사가 파일 종류에 따라 다른 뜻**이었던 것.
  아이콘 해석이 맞은 건 검증 덕이지 운이 아니지만, **"R1/R2가 뭘 뜻하냐"를 한 번 물었으면 이펙트까지 한 번에 정리됐다.**
  내가 낸 선택지도 아이콘 규칙(루트)을 기본값처럼 앞에 놓았는데 정답은 두 번째였다.
- **유저가 명시 안 한 전제** — "모든 진화 트리에 아이콘 다 그렸다"에서 *다*가 32종(루트별)인지 64종(루트×티어)인지.
  파일을 세어 32장인 걸 확인하고 진행했고 결과적으로 맞았다.
- **자율적으로 잘 결정한 것** — 진화 아이콘 배열을 3곳(HUD·LevelUpUI·EvolutionTreeUI)에 중복 배선하지 않고
  `LevelUpUI` 단독 소유 + `Instance` 경유로 간 것. `PauseMenu`가 이미 그 패턴이라 근거가 있었고, 씬 배선이 96칸에서 34칸으로 줄었다.
- **사용자가 짚어준 것** — `Effect_ArrowR1`을 "쓸 자리를 정해달라"고 미뤄뒀는데
  *"arrowR1 그거 치명타 진화에서 큰 화살 하나 나가는 그게 저 스프라이트야"* 로 바로 해결됐다. 미뤄두길 잘한 케이스.

**다음에 바꿀 것**:
- **[→ Kit] 사용자 아트를 배선하기 전에 "한 파일 = 한 그림인가"를 확인한다.**
  Unity 기본값이 Multiple이라 **자동 슬라이스가 조각을 내면 `_0`이 의도한 그림이 아니다**(이번 `Effect_Arrow*`가 정확히 그랬다).
  트리거 자명 — *새 PNG를 코드·씬에 배선하기 직전.* 기존 "아트 반영 전 파일 수정 시각 확인" 규칙의 옆자리다.
- `script-execute`에 보내는 코드는 `using`을 넉넉히 깔고 시작할 것(Linq·SceneManagement는 거의 항상 쓴다).

**메모**: 칸반에 사용자가 세션 사이에 올린 카드 2장("플테후 제안사항"·"스킬 리소스 확충")이 HANDOFF에 없었다.
`brief`가 칸반을 먼저 조회하게 해 둔 게 이번에도 값을 했다 — 다만 이번 세션은 사용자가 곧장 작업을 지시해서 `brief`를 끝까지 돌리지 않았고,
**칸반을 세션 *끝*에야 봤다.** 그래서 "스킬 리소스 확충" 카드의 체크리스트(아이콘 = 이번 작업 그 자체)를 모르고 일했다. 결과는 같았지만 순서는 거꾸로였다.

## 세션 2 — 블루베리 디펜스 (세션36)

**목표**: "할 일이 너무 많으니 노션에서 뭘 할지 추려봐" — 범위를 사용자와 정하고 그만큼 처리.

**한 일**: 칸반 카드 2장 분량 7건을 구현했다(플테후 제안 3건 + UI 폴리싱 4건).
그 뒤 아트 리소스를 우선순위로 정리해 노션 두 곳에 남겼다 — 「스킬 리소스 확충」에 **진화 20루트 이펙트 명세표**(프리팹 실측 크기),
새 카드 「아트 리소스 제작」에 **그릴 것 전부**. 카드 2장을 완료로 옮겼다.

**과정 — 잘 된 것**:
- **`brief`를 끝까지 돌린 게 이번엔 정확히 값을 했다.** 세션35 일기의 반대 케이스다 —
  「폴리싱 할일 리스트업」 카드에 사용자가 **UI 폴리싱 상세 리스트를 통째로 새로 써 둔 것**을 세션 *시작*에 발견했고,
  오늘 작업 7건 중 4건이 거기서 나왔다. HANDOFF엔 흔적이 없었다.
- **다른 세션이 동시에 돌고 있다는 걸 `git status`로 먼저 알아차린 것.** 폰트·`DamageNumber`가 수정돼 있길래
  ① 대미지 표기 작업을 **안 건드리고** ② HUD 정수 표시를 **씬이 아니라 런타임 생성으로** 넣어 씬 저장 충돌을 피했다.
  사용자에게 "폰트 어디 쓰실 거냐"고 물었더니 *"다른 세션에서 돌리는 거니 신경꺼"* — 추측이 맞았다.
- **검증에 대조군을 계속 붙인 것.** 픽업 곡선은 24케이스 도착 시뮬레이션 + **선회를 끈 대조군이 8/8 실패**하는 걸 같이 찍었고,
  그림자 지면 고정도 **보정 없으면 lift만큼 그대로 뜬다**를 먼저 재현한 뒤 0으로 만들었다.
- **"넣어줘를 받으면 이미 있는 곳부터 센다" 규칙이 실제로 발동했다** — 아트 카드를 만들기 전에
  기존 3개 카드(스킬 리소스 확충·뉴캐릭터 이펙트·폴리싱)에 이미 걸린 항목을 세어 중복을 뺐다.

**과정 — 막힌 것 / 마찰**:
- 🔴 **노션에 한글을 유니코드 이스케이프로 보내다 오타를 네 번 냈다.** `핫뚜1`→`핫뙐1`→`핫뜬1`, `만렙`→`만렉`,
  `곡선`→`공선`, `몸이 떠도`→`메가 띄어도`. 원인은 하나다 — **코드포인트를 손으로 계산했다.**
  JSON에 한글을 **그대로 써도 아무 문제가 없었다**(같은 세션에 `.asset`·`HANDOFF.md`는 직접 써서 멀쩡했다).
  사용자 눈에 보이는 문서에 오타를 심었고, 고치는 데 왕복 3번을 더 썼다.
- `API-update-page-markdown`의 `update_content`가 한 항목만 조용히 매칭 실패했다(체크박스가 안 바뀜).
  **반환된 마크다운을 눈으로 확인해서** 잡았다 — 성공 응답을 믿었으면 못 봤다.

**AI 협업 체크** *(코드 버그 말고 과정 레벨로)*:
- 🔴 **사용자가 짚어준 것 — "그림자가 뜨면 안될듯".** 그런데 이건 **내가 HANDOFF에 직접 적어놓고 넘긴 자리**다:
  *"⚠️ 콩콩이가 점프하면 그림자도 같이 떠오른다. 어색하면 지면 y 고정이 필요하다."*
  `unity-mcp` 스킬의 **"위험 지점을 글로 지목할 수 있으면 재현 조건도 짤 수 있다"** 와 정확히 같은 함정인데,
  그 규칙은 *"확인 부탁드립니다"로 넘길 때*를 말해서 **"어색하면 나중에 고치죠"로 넘길 때**엔 발동을 안 했다.
  지목한 순간 고칠 방법도 알고 있었다 — 실제로 지적받고 5분 만에 고쳤다.
- **추측으로 진행한 것 — `swing_StartLev` 노드의 위치·선행 조건.** 메모리에 *"트리 그래프 설계는 사용자 담당"* 이 있어서
  `arrow_StartLev`를 **완전 미러링**만 하고 "임시 배치이니 옮기라"고 카드·HANDOFF 양쪽에 명시했다. 이 절충은 재현할 만하다.
- **사용자가 뒤집은 것 — 아트 카드의 중복 제외.** 나는 "이미 다른 카드에 있으니 빼겠다"고 했는데
  *"싹다 새로운 카드에 넣어줘, 모아서 한눈에 보게!!"* 였다. **규칙(중복 금지)이 틀린 게 아니라 목적(한눈에 보기)이 달랐다** —
  중복을 뺄지 말지는 내가 정할 게 아니라 **"어디서 볼 것이냐"를 물었어야 하는 자리**였다.
- **자율적으로 잘 결정한 것** — 사용자가 "정수 UI 넣어줘"라고 했을 때 배치를 추측하지 않고
  HUD 자식 18개의 앵커·좌표를 씬에서 **읽어 본 뒤** "좌상단이 유일하게 비었다"를 근거로 정한 것.

**다음에 바꿀 것**:
- **[→ Kit] 노션·JSON에 한글을 쓸 땐 유니코드 이스케이프를 만들지 말고 한글을 그대로 쓴다.**
  트리거 자명 — *노션 툴에 한글이 들어가는 문자열을 넘기기 직전.* 손으로 계산한 코드포인트는 이번에 **4번 중 4번 틀렸다.**
- **[→ Kit] 문서에 "어색하면 나중에 고치면 된다"고 쓰는 순간, 그건 지금 고칠 수 있다는 뜻이다.**
  트리거 자명 — *HANDOFF·카드에 "⚠️ ~하면 ~가 필요하다"를 쓰려는 순간.* 고치는 법을 적을 수 있으면 고칠 수 있다.
  기존 "재현 조건도 짤 수 있다" 규칙의 옆자리인데, 그건 **검증**을 넘길 때만 말하고 **미완성**을 넘길 때는 안 말한다.

**메모**: 병렬 세션이 같은 저장소를 만지는 상황이 처음이었다. `git status`를 **커밋할 때가 아니라 세션 중간에** 한 번 본 게 결정적이었다 —
안 봤으면 씬을 저장했을 것이고 두 세션이 엉켰다. 커밋도 경로를 나눠야 한다.
