## 세션 1 — 블루베리 디펜스

**목표**: 플레이 피드백 4건 처리 — 암살 경험치 너프, 방패 블루베리(관통·오브 차단) 신규 적, 진화 UI juice, 그리고 "후반 일반공격이 너무 세다"의 원인 분석·조정.

**한 일**: 암살 처치경험치 배율 절반(1.5/3/4→1.25/2/2.5). 방패 블루베리를 메커니즘(Enemy.blocksProjectiles → Projectile/Orb 소멸)부터 프리팹·5프레임 애니·스포너 배선·9스테이지+ 등장까지 풀스택으로 구현. 진화 UI에 스태거 pop-in + 진화가능 노드 펄스. 기본공격 데미지는 코드를 따라가 "곱연산 채널 과다 수렴 + 크리 상시100%"를 원인으로 짚고, 유저와 방향 합의 후 크리확률 70%캡·힘 크리배율 성장 축소·힘 path0/path2 곱→덧셈 통합으로 조정. 전부 컴파일만 확인, 밸런스 체감은 다음 플레이 몫.

**과정 — 잘 된 것**:
- 데미지 분석을 "구체 수치 예시(≈3,800/히트)+채널별 표"로 제시하니 유저가 바로 방향(①크리 구조 ②곱→합)을 골라줬다. 추상적 "곱연산이 문제"보다 실제 곱셈 사슬을 끝까지 펼쳐 보인 게 논의를 빠르게 수렴시켰다.
- 방패 블루베리 프리팹을 손으로 YAML 복제(새 GUID meta)해서 만들었는데 Unity가 정상 인식 — 프리팹 내부 fileID는 파일-로컬이라 복제해도 충돌 안 난다는 걸 활용. 이후 애니 클립/컨트롤러는 하드 YAML 대신 `script-execute`로 Unity API(AnimationUtility, AnimatorController.CreateAtPathWithClip, PrefabUtility)를 돌려 안전하게 처리.
- 스프라이트 방향: CLAUDE.md 시각 원칙대로 원본 5장을 Read로 직접 보고 "방패가 오른쪽=진행방향"임을 확인 → 블루베리 복제본의 FlipX=1을 0으로 정정. 안 봤으면 방패가 뒤통수에 달릴 뻔.

**과정 — 막힌 것 / 마찰**:
- 새 스프라이트 임포트 설정이 기본값(PPU100·Bilinear·압축·Multiple)으로 들어와 있어 우리 컨벤션(32·Point·무압축·Single)으로 다시 맞춰야 했다. 매번 반복되는 잡일 — 임포트 프리셋이 있으면 좋겠다.
- 스포너 분기가 else-if 체인(elite→…→shield 순)이라, shieldChance를 표값 그대로 두면 후반 elite(0.7~0.8)가 스폰을 다 먹어 방패 실제 등장률이 확 희석됨. 값 설정 시 이 희석을 머리로 계산해 보정해야 했다.

**AI 협업 체크**:
- **잘 한 자율 결정**: 방패의 "차단 범위"를 유저가 "관통·오브"만 언급했지만, 회오리/낙뢰/독수리는 투사체가 아니라 제외하는 걸로 스스로 정리하고 명시 — 되묻지 않고 합리적 기본값 + 근거 제시.
- **암묵 전제**: shieldChance 구체값을 유저가 안 정해줬고 나도 안 물음 — "9스테이지부터"만 명시됐지 빈도는 감으로 잡았다. 벽 몹은 빈도가 체감을 크게 좌우하니, 실은 "얼마나 자주?"를 한 번 확인했어도 좋았다(다만 밸런스는 어차피 플레이테스트로 조정할 거라 큰 손해는 아님).
- **곱→덧셈 통합**은 유저가 "2번 해주고 설명해줘"로 명확히 지시 — 구조 변경이라 before/after 수식과 수치표로 설명한 게 적절했다.
