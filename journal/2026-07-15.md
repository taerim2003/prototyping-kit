## 세션 1 — 블루베리 디펜스: 아웃게임(메타) 계층 + 스킬트리 전환

**목표**: 노션의 아웃게임 기획을 확인하고 메타 프로그레션(정수 재화 + 태양의 가호 업그레이드)을 구현.

**한 일**:
- 아웃게임 메타 루프를 통째로 구축(저장·정수 획득/흡입 드랍·판종료 적립·Title 씬·리스트 상점 8종·인게임 반영). 결정적 로직은 script-execute로 검증.
- 리스트 상점이 밋밋하다는 피드백 → **노드 스킬트리(2자원 게이팅)로 방향 전환** 결정.
- **커스텀 비주얼 노드 에디터**(EditorWindow + ScriptableObject) 제작 → 사용자가 28노드 트리를 직접 설계. `ActiveSkill` 노드타입 추가.

**과정 — 잘 된 것**:
- 대량 씬/UI 구축을 개별 MCP 프리미티브 대신 **`script-execute`(에디터 스크립트)로 프로그래밍적 일괄 생성** → Canvas renderMode·Collider 자동맞춤 등 알려진 MCP 함정을 통째로 우회. 빠르고 재현가능.
- 새 .cs 작성 후 매번 assets-refresh + console-get-logs(Error) + 타입참조 스크립트로 **컴파일·인식 즉시 검증** → "새 파일 미인식" 함정을 조기에 배제.
- 리스트 상점의 스탯반영 계층(MetaBonuses/Applier)을 스킬트리에서 **그대로 재사용**하게 설계 → 방향 전환 비용을 UI/구조로 한정.
- 데이터를 ScriptableObject에 두고 에디터·런타임이 **같은 에셋을 공유**하게 해서, "텍스트 스키마 주고받기" 단계를 없앰(사용자 제안이 좋았음).

**과정 — 막힌 것 / 마찰**:
- **노션 재연결에 세션 초반을 다 씀.** 문서(ONBOARDING)가 `홈\.mcp.json` 방식을 정답처럼 적어놨는데, 현재 Claude Code는 그 위치를 자동로드하지 않음 → user scope(`~/.claude.json`) 등록이 실제 해법이었음. 진단(토큰 유효성 curl·node 확인)까지 하고서야 규명.
- **토큰을 `claude mcp add --env`로 넘기다 에러 메시지에 평문 노출**됨. 결국 node로 `~/.claude.json` 병합해서 해결. 재발급 필요.
- **IMGUI 노드 에디터 팬/줌**에 왕복이 많았음: (1) MouseDown에서 hotControl을 안 잡아 드래그 이벤트 자체가 안 옴, (2) GUI.matrix 줌이 클립을 안 따라와 화면이 잘림. 결국 줌을 빼서 안정화. 인터랙티브 테스트를 내가 못 하니 사용자 왕복으로 디버깅(툴바에 이벤트 디버그 라벨을 띄워 원인 좁힘).

**AI 협업 체크**:
- 추측으로 진행? — 초반 노션 이슈에서 내가 "프로젝트에 고칠 게 없다"고 **성급히 단정**했다가 사용자가 "MD에 적어놨다"고 지적. 문서부터 grep했어야 함.
- 암묵 전제? — 아웃게임 세부 수치(정수 획득방식·비용곡선)는 노션에 없어서 AskUserQuestion으로 명시화한 건 좋았음. 반대로 저긴 잘 물음.
- 자율 결정 잘한 것? — 씬/UI를 script-execute로 일괄 생성, 스탯계층 재사용 설계, 데이터=에셋 공유 구조. 재현할 것.

**다음에 바꿀 것**:

**메모**:

## 세션 2 — 스킬트리 런타임 완성 + UI 대개편 + 인게임 밸런스 배치

**목표**: 스킬트리 런타임을 붙이고(저장·규칙·UI·효과훅), 사용자 피드백(트리 UI 개편 10건 + 인게임 개선 10건)까지 처리.

**한 일**:
- 스킬트리 **런타임 전 계층**: 저장/진행(3자원·깊이별 비용·환불 캐스케이드) + 효과적용(28노드 전부 실동작) + 인게임 트리 UI(마스킹·호버툴팁·클릭구매·우클릭환불·줌) + 리스트 상점 완전 제거.
- 인게임 배치 10건(오버힐 표시·ESC 일시정지·기본공격 너프·스테이지 길이 절반 등) — 전부 코드/에셋으로.
- 착수 전 **AskUserQuestion으로 설계 확정**(일회성 개방·자원 종류·빌드셋 포함 여부) 후 `SKILLTREE_DESIGN.md`에 박제.

**과정 — 잘 된 것**:
- 세션1의 패턴(script-execute 일괄 빌더 + refresh/logs/typeof 컴파일검증 + 결정적 로직 script-execute 테스트)을 그대로 재사용해 대량 작업을 빠르게. available 파생·환불 캐스케이드·효과 누적을 매번 기대값과 대조 로그로 검증.
- 설계 애매점을 **먼저 질문**하고 진행(레벨 없는 일회성 개방·가루 자원). 사용자가 도중에 규칙을 바꿔도(→ 일회성) 캐리어 구조(MetaBonuses/SkillEffects) 덕에 반영이 국소적.
- 씬 편집이 불가피한 값(방패 스폰·오버힐)은 알고 보니 **StageTable 에셋/코드 상수**라 씬 안 건드리고 처리. "이 값이 씬에 있나 에셋에 있나"를 먼저 확인한 게 유효.

**과정 — 막힌 것 / 마찰**:
- **🔴 사용자 씬 꾸밈 데이터 손실(가장 큰 실수).** 빌더 `script-execute`가 `EditorSceneManager.OpenScene("Title.unity", Single)`로 씬을 여러 번 새로 열었는데, 사용자가 **저장 안 한 Title 꾸밈**이 그때 조용히 버려짐. git엔 커밋 전이라 복구 불가 → 사용자가 직접 복구. 강한 항의를 받음. **에디터의 사용자 작업물을 내가 파괴할 수 있다**는 걸 과소평가.
- MonoBehaviour 여러 개를 한 .cs에 넣으면 **파일명 아닌 보조 클래스가 프리팹/씬 저장 시 스크립트 참조를 잃음**(BuildSlotUI가 프리팹에서 missing). 런타임 AddComponent 전용이면 같은 파일 OK, **씬/프리팹에 저장되는 컴포넌트는 반드시 자기 파일**로. 규칙 확립.
- 컴파일 실패 사이클 중 Controllers에 **missing script 컴포넌트**가 남아 경고 유발 → `RemoveMonoBehavioursWithMissingScript`로 청소.

**AI 협업 체크**:
- 추측으로 진행? — 밸런스 수치(#8 기본공격 70%·#10 스테이지 길이)는 만렙 레벨/총시간을 정확히 모른 채 감으로 잡음. 의도(70%)는 밝히되 "실측 필요"로 명시. OK.
- 파괴적 작업 확인? — **못 했음.** 씬을 스크립트로 열기 전에 "저장했냐"를 물었어야. 이번의 핵심 반성.
- 자율 결정 잘한 것 — 씬 대신 에셋/코드 경로 선택, PauseMenu를 RuntimeInitializeOnLoad 자동부트스트랩으로 **씬 편집 0**으로 구현. 재현할 것.

**다음에 바꿀 것**:
- **[→ Kit] 씬 편집 스크립트 안전수칙**: 사용자가 열어둔 씬(특히 손으로 꾸민 Title류)을 `OpenScene(Single)`로 열지 말 것. 열어야 하면 **저장 여부부터 확인**. 코드/에셋으로 우회 가능한지 먼저 판단. (메모리 `dont-overwrite-user-scenes` 등록함.)
- 새 MonoBehaviour는 **씬/프리팹 저장 여부**를 먼저 판단해 파일 분리 결정.
