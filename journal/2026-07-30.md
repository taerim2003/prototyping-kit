## 세션 1 — 블루베리 디펜스 (세션 20)

**목표**: 스폰 리듬에 "무리로 좌라락 → 쉬었다 다음 무리"(BTD6식)를 섞고, 새로 그린 적 2종(콩콩이·서핑)을 해안가 맵 전용 스테이지 세트에 배치.

**한 일**: 웨이브 스폰(`StageData.burstSize`/`burstRest`) → 콩콩이(포고스틱 도약)·서핑(바다에서 대각선 돌진) 2종 → 해안가 전용 25판 테이블 → 레인 내리기(`cameraYLift`) → 서핑 디테일 3종(무리 두께·파도 너울·속도 개체차). 마지막에 문서 전체 정리(HANDOFF 497→118줄, GDD 스펙 갱신).

**과정 — 잘 된 것**

- **배경 그림을 픽셀 단위로 분석해서 좌표를 정한 것.** "서핑이 모래 위에 있다"는 지적을 받고 배경 PNG의 행을 하늘/바다/모래로 분류해 수평선 +1.33, 물가 −0.5~0을 뽑았다. 눈대중으로 값을 넣고 되묻는 왕복이 없었다. 스프라이트 방향(flipX)도 6배 확대해서 보고 정했다 — 세션14에 라이더 방향을 추론으로 넣었다가 틀렸던 것과 대조적.
- **기존 코드 경로 재사용.** 서핑을 새 이동 로직 없이 종이비행기의 `isDiveFlyer`에 스폰 띠만 바꿔 얹었다. 신규 필드 3개가 전부 기본값 0이라 기존 적 9종은 무변경 — 이걸 프리팹 전수 확인으로 증명했다.
- **"되돌리기 쉬운 지점"을 명시한 것.** 검증된 밸런스(기본 맵)에 손댄 6판은 원래 값을 문서에 적어 뒀다. 밸런스 변경은 언제나 되돌릴 수 있어야 한다.

**과정 — 막힌 것 / 마찰**

- 🔴 **`SaveCurrentModifiedScenesIfUserWantsTo()`로 Unity를 5분 넘게 멈춰 세웠다.** 모달이 떠서 MCP가 전부 죽었고, 사용자가 창을 눌러줄 때까지 아무것도 못 했다. **비대화형 자동화에서 "UserWantsTo" 계열 API는 금지.** 이후엔 `EditorSceneManager.SaveScene`을 직접 썼다.
- 🔴 **게임오버(`timeScale=0`) 상태에서 값을 재고 "버그"라고 오판했다.** 흔들림이 0으로 안 잦아든다고 읽었는데, 실제로는 `Time.deltaTime`이 0이라 마지막 값에 굳어 있었을 뿐. `Time.time`이 이전 측정과 **똑같이 20.6**이었다는 명백한 신호를 그냥 지나쳤다. → **플레이모드 측정 전에 시간이 흐르는지부터 확인.**
- **플레이 중엔 스크립트가 컴파일 안 된다는 걸 두 번 잊었다.** 코드를 고치고 바로 재진입해서 옛 코드로 측정했다. 플레이 종료 → 컴파일 확인 → 재진입 순서가 필요.
- **MCP `script-execute`는 호출마다 독립 어셈블리**라 static으로 프레임 간 상태를 못 넘긴다. 시계열 측정을 하려다 한 번 헛발질했고, "누적되면 반드시 벗어나는 회랑"을 판정식으로 세우는 방식으로 우회했다. **한 번에 판정 가능한 불변식을 설계하는 게 시계열 샘플링보다 낫다.**
- **프리팹의 `SpriteRenderer.sprite`를 직접 대입했더니 조용히 무시됐다.** 다른 필드는 다 들어갔는데 스프라이트만 안 들어가서 검증 로그로 잡았다. `PrefabUtility.LoadPrefabContents` + `SerializedObject`로 해결. → **에셋을 만들면 반드시 되읽어서 확인할 것.** 이번엔 검증 로그가 있어서 잡혔다.

**AI 협업 체크**

- **추측으로 진행한 것**: "새로운 맵"이 해안가(Map_Wide15)라고 단정하고 물어보지 않았다. 맞긴 했지만(서핑+바다 배경) 한 줄 확인이 쌌다.
- **암묵적 전제**: 레인 높이 요청("좀 내려줘")에서 *얼마나*가 없었다. 배경 그림에서 근거를 뽑아 2.2로 정하고 그 근거를 같이 보고했다 — 숫자만 던졌으면 다시 물어야 했을 것.
- **자율 결정 중 잘한 것**: 레인을 내릴 때 **플레이어/적 좌표 대신 카메라를 올린 것.** 월드 좌표를 내렸으면 절대 y를 쓰는 회오리 착지선(`groundY=0`)이 적보다 2유닛 위에 뜬다. 시각 결과는 같은데 회귀 위험만 없앤 선택이라 문서에 "반대로 바꾸지 말 것"으로 남겼다.
- **덜 한 것**: 세션19 피드백 5개 중 2번(레인 높이)을 처음에 빼먹고 "미착수"로만 적어놓고 넘어갔다. 사용자가 짚어줘서 했다. **인계 문서의 미해결 목록을 작업 범위로 자동 편입하지 않은 게 문제.**

**다음에 바꿀 것**

- **[→ Kit] Unity 자동화 금지 API 목록을 CLAUDE.md에 추가**: `SaveCurrentModifiedScenesIfUserWantsTo`, `EditorUtility.DisplayDialog` 등 — 모달을 띄우는 API는 MCP 세션을 통째로 멈춘다.
- **[→ Kit] 플레이모드 측정 체크리스트**: ① `Time.timeScale`·`Time.time`이 흐르는가 ② 플레이 종료 후 컴파일이 끝났는가 ③ 한 프레임에 판정 가능한 불변식인가.
- **세션 시작 시 HANDOFF의 "미해결" 목록을 사용자와 한 번 훑고 이번 범위를 확정하기.** 이번엔 2번 항목을 놓쳤다.
- **에셋을 코드로 만들면 되읽어서 검증하는 걸 기본 절차로.** 이번에 스프라이트 누락을 잡은 게 이 덕분이다.

**메모**

- HANDOFF가 497줄까지 불어나 있었다(자기 규칙은 "한 화면"). 세션마다 추가만 하고 삭제를 안 한 결과. 이번에 118줄로 줄이면서 구조적 함정은 ARCHITECTURE로, 게임 스펙은 GDD로 옮겼다. **문서가 셋인데 "무엇을 어디에 쓰는가"가 안 지켜지면 전부 HANDOFF로 흘러든다.**
- GDD가 특히 낡아 있었다(종료 조건이 아직 "시간 종료", 몬스터 표가 5종·옛 수치, 진화가 3path×3tier). **GDD는 아무도 안 읽으니 안 고쳐지고, 안 고쳐지니 더 안 읽는다.** 이번처럼 주기적으로 코드와 대조해야 한다.
- 남은 큰 작업: 광활한 밭 배경(640×360), 공중 유닛 2종(지그재그/가로지르기), 해안가 실플레이 검증.

## 세션 2 — 블루베리 디펜스 (세션 21)

**목표**: 세션20 결과물을 사용자가 실제로 플레이하고 쏟아낸 피드백 16건을 한 세션에 반영.

**한 일**: 피드백을 코드/데이터 위치로 매핑 → 방향이 갈리는 2건만 먼저 질문 → 나머지 14건 일괄 처리. 보물상자를 3지선다에서 뱀서식 자동 보너스로 재설계, 보스 판을 15·20·25로 확장, 진화 설명 전체를 수치 없는 BTD6 파라곤식 문구로 교체, 해안가 25판 테이블 전면 재저작(하늘 유닛 비중 13%→59%), 호밍 커브에 쿨감 편입. 전 변경을 에디터에서 되읽어 검증.

**과정 — 잘 된 것**

- **16건을 받고 바로 코드부터 읽은 것.** "무엇을 고칠까"를 되묻지 않고 `grep`으로 16건의 실제 위치를 먼저 특정했다. 그 결과 질문이 2개로 줄었고, 그 2개는 코드를 봐도 답이 안 나오는 진짜 설계 결정이었다(보스 판 정책, 보물상자 형태). **모호함을 세기 전에 코드를 읽으면 모호함의 대부분이 사라진다.**
- **커플링을 스스로 찾아낸 것.** 접촉 거리를 1.35→2.55로 벌리라는 요청 하나가 `HeadbuttLungeDistance`(안 늘리면 허공에 박치기)와 `AmbushBandMaxX`(안 내리면 중간 소환이 대응 불가)를 동시에 깨뜨렸다. 요청받지 않은 두 상수를 같이 고치고, **변경 전과 동일한 여유값(0.46유닛)이 나오는지 엔진에서 수식으로 확인**했다. 눈으로 봤으면 "가끔 억울하게 맞네" 정도로 넘어갔을 버그다.
- **쓴 값을 전부 되읽어 검증한 것(세션20 교훈 적용).** YAML을 직접 써 놓고 `AssetDatabase.LoadAssetAtPath`로 되읽어 로그를 찍었다. 실제로 PowerShell 스크립트가 **조용히 아무것도 안 바꾼 적**이 있었는데(해시테이블 키가 int인데 비교는 string) `git diff`가 잡았다. 검증 습관이 이번에 값을 했다.

**과정 — 막힌 것 / 마찰**

- 🔴 **"성장률 표"를 완전히 잘못 읽고 엉뚱한 표를 만들었다.** 사용자가 "호밍미사일 쓸 때마다 강화되는 거, 몇 번 쓰면 얼마나 세지는지"를 물었는데 나는 **레벨업 커브 표**를 냈다. 되돌아보면 신호가 셋이나 있었다 — ① "쿨타임대로 계속" ② "여러 번 써야 성장률이 올라가는 구조" ③ 이 게임의 진화 루트 이름이 아예 **"성장률 강화"**다. 도메인 용어가 이미 정해져 있는데 일반적 의미로 읽었다. **왕복 한 번을 통째로 날렸다.**
- **음성 받아쓰기 특유의 숫자 뭉개짐에 두 번 걸렸다.** "이 십 라운드"가 15인지 20인지, "십 라운드에 보스"가 10판 보스인지 15판 보스인지 갈렸다. 질문해서 풀었지만(정답: 15·20 둘 다 보스 판), **숫자가 애매하면 추론하지 말고 물어보는 게 맞다**는 게 확인됐다.
- **"벽 벽 애들"을 물어보지 않고 방패 블루베리로 단정했다.** 벽 스테이지(7·9·13·22)일 수도 있었는데 "파괴가 편할 것 같다"는 문맥으로 방패라고 결론냈다. 맞을 가능성이 높지만 **보고할 때 가정이라고 명시하지 않고 그냥 처리해버렸다.**
- **내 컴파일 요청이 사용자의 미저장 인스펙터 편집을 디스크로 밀어냈다.** `RequestScriptCompilation` → 도메인 리로드 → Unity가 dirty 에셋을 자동 저장. `Prog_Orb`·`Prog_Whirlwind`가 내가 안 건드렸는데 변경으로 잡혔다. `git status`를 확인해서 발견하고 사용자에게 "내 변경이 아니다"라고 보고했다. **에디터를 공유하는 작업에서는 커밋 직전 git status의 모든 항목을 설명할 수 있어야 한다.**
- PowerShell 5.1에서 `Out-File -Encoding utf8`이 **BOM을 붙인다.** Unity YAML에 BOM이 들어갈 뻔했다. `[System.IO.File]::WriteAllLines` + `UTF8Encoding($false)`로 해결.

**AI 협업 체크**

- **물어봤어야 하는데 추측한 것**: "벽 벽 애들"(위 참조). 그리고 하늘 유닛 "5배"를 곱셈이 아니라 "전체의 약 60%"로 재해석했는데 — else-if 확률 사슬이라 단순히 5를 곱하면 1.0을 넘어서 불가능했다. 재해석 자체는 옳았지만 **"5배는 구조상 불가능해서 이렇게 읽었다"를 먼저 말했어야** 했다.
- **암묵적으로 넘어간 전제**: "물량이 적다"와 "15~20판이 너무 길다"가 표면상 충돌했다. 스폰 *간격*을 절반으로 줄이는 것으로 둘 다 만족시켰는데, 이 해석을 사용자에게 확인받지 않고 진행했다. 결과는 맞을 것 같지만 **모순되는 두 요구를 받으면 그 모순을 먼저 지적하는 게 낫다.**
- **자율 결정 중 잘한 것**: 진화 설명에서 수치를 **전부** 뺀 것. 절충(제목은 기능어, 설명만 추상)도 가능했지만 사용자 의도가 "동작을 예측 못 하게"였으므로 끝까지 밀고, 되돌릴 절충안을 HANDOFF에 적어 뒀다. **의도를 반만 실행하면 의도대로인지 판단조차 안 된다.**

**다음에 바꿀 것**

- **[→ Kit] 도메인 용어 사전을 먼저 확인하기.** "성장률"처럼 프로젝트에 이미 고유 의미가 있는 단어를 일반어로 읽으면 통째로 헛일한다. 요청에 나온 명사가 코드에 그 이름으로 존재하는지 `grep`부터.
- **[→ Kit] 상수를 바꾸기 전에 "이 값과 한 세트인 값"을 찾기.** 접촉 거리 건이 전형. 주석에 다른 상수 이름이 등장하면 그건 커플링 신호다. 이번에 고친 3종은 서로를 가리키는 주석을 달아 뒀다.
- **음성 입력의 숫자는 신뢰하지 말 것.** "이 십/십오"류가 갈리면 무조건 확인.
- **커밋 전 `git status`의 모든 줄을 설명할 수 있는지 자문하기.** 설명 못 하는 줄이 있으면 그게 사고다.

**메모**

- 이번 세션 변경은 **전부 데이터·상수 수준이고 새 시스템이 거의 없다.** 그래서 16건이 한 세션에 들어갔다. 세션20이 시스템(웨이브·신규 적)을 깔아 놓은 덕분에 이번엔 "손잡이만 돌리면" 되는 상태였다 — 손잡이를 데이터로 빼 두는 투자가 여기서 회수됐다.
- 반대로 **손맛 검증은 하나도 못 했다.** 16건 전부 "숫자는 맞는데 감각은 미검증"이다. 다음 세션은 전부 플레이 검증이 될 것이고, 그래서 테스트 체크리스트를 HANDOFF에 미리 만들어 뒀다.
- 미해결로 남긴 판단 2개: 호밍 2차 진화(캐스트 100회에 ×29)에 상한이 없는 것, 보스 판 3개가 되면서 종료 보물상자를 3개 잃는 것. 둘 다 실플레이 전엔 결정 못 한다고 보고 손대지 않았다.
